## 5. Общий шкаф ШВ7.8 — ключевая особенность

### 5.1. Постановка

Из восьми установок **шесть имеют отдельные шкафы** (ШВ1…ШВ5 и шкаф В6), а **В7 и В8 работают от общего шкафа ШВ7.8**.

**Требование ТЗ:** «В7 и В8 отображаются **отдельными экземплярами**, несмотря на общий шкаф ШВ7.8».

**Следствие:** один экземпляр = одна установка (как и для остальных шести). Общий шкаф **не** объединяет В7 и В8 в один экземпляр.

**Зачем тогда шкаф в модели ПБЭ:**
1. показать оператору, что установка работает **от общего шкафа** с соседней;
2. обеспечить **общие команды** для этой пары (пуск/стоп/сброс на две установки сразу);
3. обеспечить общие **аварийные признаки шкафа**, которые относятся к обеим установкам.

### 5.2. Разделение индивидуальных и групповых параметров

Реализация — **два независимых набора**, как и в ПБЭ № 6:

| Набор | Префикс | Примеры |
|---|---|---|
| **Индивидуальные** | без префикса | `ВклУст`, `СтопУст`, `СбросАварии`, `СбросЗуммера`, `РаботаВент1`, `АвA001` … |
| **Групповые** | `Гр` | `ГрНомерШкафа`, `ГрВклШкафа`, `ГрСтопШкафа`, `ГрСбросАварий`, `ГрСбросЗуммера`, `ГрРаботаШкафа` … |

**Правила:**
1. Для **шести** установок с отдельными шкафами `ГрКолУстановок = 1`, `ГрНомерШкафа` = `ШВ1`…`ШВ5`, `В6`.
2. Для **В7 и В8** `ГрКолУстановок = 2`, `ГрНомерШкафа = ШВ7.8` **у обоих**.
3. Групповые параметры **не подменяют** индивидуальные.
4. ДИГАМ подключает групповые параметры **одного** из пары к общему тегу шкафа ШВ7.8; второй экземпляр получает то же значение.

> **Отличие от ПБЭ № 6.** Там общий шкаф был у 3 и у 10 установок. Здесь — **только у двух** (В7, В8), а шесть работают индивидуально. Поэтому настройка `ГрКолУстановок` принимает значение **1** для шести экземпляров.

## 6. Аварии A001–A007 — отдельными признаками

ТЗ: «аварии **A001–A007** отдельными признаками».

**Масок DINT нет. `GetBit` в программе не вызывается.** ТЗ п. 3.

| Код | Параметр-признак | Тип | Текст для отображения |
|---|---|---|---|
| **A001** | `АвA001` | BOOL | `A001` |
| **A002** | `АвA002` | BOOL | `A002` |
| **A003** | `АвA003` | BOOL | `A003` |
| **A004** | `АвA004` | BOOL | `A004` |
| **A005** | `АвA005` | BOOL | `A005` |
| **A006** | `АвA006` | BOOL | `A006` |
| **A007** | `АвA007` | BOOL | `A007` |

**Формирование текста аварии.** ТЗ п. 3: «текст аварии формируется **по признаку**». Поэтому:
* имена параметров **точно соответствуют кодам производителя** (`АвA001`…`АвA007`) — это позволяет ДИГАМ подключить теги без переименования;
* в панели «Аварии» окна 8.1 каждой строке соответствует свой код;
* параметр `ТекстАварии` собирает перечень активных кодов (например `A001, A004`).

> **Расшифровка кодов производителем не передана** (допущение `D-15`). Поэтому тексты в панели — **коды**, а не словесные описания. При получении расшифровки от Zentec достаточно дополнить таблицу текстов; параметры и программа **не меняются**.

## 7. Положения клапанов

ТЗ прил. 1 ч. 2: «**положения клапанов**».

| Параметр | Тип | Диапазон | Назначение |
|---|---|---|---|
| `ПоложениеКлапанаПрит` | REAL | 0…100 % | Аналоговое положение клапана притока |
| `ПоложениеКлапанаВыт` | REAL | 0…100 % | Аналоговое положение клапана вытяжки |
| `КлапанПритОткрыт` | BOOL | — | Конечник «открыт» |
| `КлапанПритЗакрыт` | BOOL | — | Конечник «закрыт» |
| `КлапанВытОткрыт` | BOOL | — | Конечник «открыт» |
| `КлапанВытЗакрыт` | BOOL | — | Конечник «закрыт» |
| `КлапанПритТекст` | STRING | — | Состояние текстом: «Открыт» / «Закрыт» / «В промежуточном» / «Нет данных» |
| `КлапанВытТекст` | STRING | — | То же |
| `КлапанПритПромежут` | BOOL | — | Признак промежуточного положения |
| `КлапанВытПромежут` | BOOL | — | То же |

**Алгоритм определения положения:**
* если `Открыт` = TRUE → «Открыт»;
* если `Закрыт` = TRUE → «Закрыт»;
* если ни один конечник не сработал, но аналоговое положение > 5 % и < 95 % → **«В промежуточном»** (признак `Промежут` = TRUE);
* иначе → «Нет данных».

> **Почему отдельный признак «в промежуточном».** Для клапана вентиляции застревание в промежуточном положении — самостоятельная неисправность, которую нужно видеть. Просто «не открыт и не закрыт» оператору ничего не говорит.

## 10. Команды сброса аварий и зуммера

ТЗ прил. 1 ч. 2: «команды **сброса аварий и зуммера**».

### 10.1. Сброс аварий

| Параметр | Тип | Напр. | Назначение |
|---|---|---|---|
| `СбросАварии` | BOOL | Вых | Индивидуальная команда сброса аварий |
| `СбросАварийВыполнен` | BOOL | Выч | Признак: сброс выполнен |
| `АварииКвитированы` | BOOL | Выч | Все активные аварии квитированы |

### 10.2. Сброс зуммера — специфика ПБЭ № 8

| Параметр | Тип | Напр. | Назначение |
|---|---|---|---|
| **`СбросЗуммера`** | BOOL | Вых | **Команда сброса зуммера** |
| **`ЗуммерАктивен`** | BOOL | Вх | Зуммер звучит (от установки) |
| **`ЗуммерВключен`** | BOOL | Выч | Зуммер должен звучать (по авариям) |
| **`ЗуммерОтключенОператором`** | BOOL | Выч | Оператор сбросил зуммер, но авария осталась |
| `ЗадержкаЗуммера` | TIME | Вых | Задержка включения зуммера, с |

**Логика:**
1. При появлении любой неквитированной аварии → `ЗуммерВключен := TRUE`.
2. Оператор нажимает «СБРОС ЗУММЕРА» → `СбросЗуммера := TRUE` → `ЗуммерОтключенОператором := TRUE`, зуммер замолкает, **авария остаётся**.
3. При появлении **новой** аварии → зуммер снова включается (признак «отключён оператором» сбрасывается).

> **Зачем различать «сброс аварии» и «сброс зуммера».** Это два разных действия оператора. «Сброс зуммера» — «я слышу, иду разбираться», авария при этом сохраняется в журнале. «Сброс аварии» — попытка квитировать и снять аварию. Смешивать их нельзя.
