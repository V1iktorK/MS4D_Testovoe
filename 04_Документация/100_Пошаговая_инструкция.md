# 100. Пошаговая инструкция исполнителю: что делать в MasterSCADA 4D 1.3.10.37086

**Кому:** пользователю («руки»).
**Что это:** единый порядок действий от пустого проекта до сданной библиотеки. Все операции расписаны один раз — в **Блоке 1 «Общие операции»**, дальше по тексту идут только ссылки на них вида `→ О-5`.

**Обозначения:**

* `О-N` — операция из Блока 1;
* `П-N` — шаг порядка работ;
* `(?)` — подпись пункта меню или кнопки, которую **не удалось подтвердить** ни по Примеру ПБЭ, ни по реестрам установленной сборки (см. `010_Сверка_со_средой_1.3.10.37086.md` §5). Таких подписей осталось две: создание библиотечного элемента и экспорт библиотеки в `.mslb`. Смысл операции однозначен — если подпись не находится, напишите мне, что видите в меню.
* Без `(?)` — подпись **проверена**: из рисунков А.1–А.6 Примера ПБЭ, из схемы проекта или из реестров типов и свойств установленной сборки (`Types\**\*.xml`).

**Материалы, которые нужны открытыми всё время:** `NN_ПБЭ_XX/параметры.md`, `окна_и_связи.md`, `тесты.md`, `сборка.md`, `st/Программа_ST_1.st`.

# Блок 1. Общие операции (описываются один раз)

## О-1. Создать проект разработки

1. Запустить **MasterSCADA 4D 1.3.10.37086** (проверенная сборка; версия ТЗ — 1.3.10.34633, отличия в `010_Сверка_со_средой_1.3.10.37086.md`).
2. `Файл` (?) → `Создать` (?) → `Проект` (?). Выбрать **проект разработки** (не рабочий проект ДИГАМ — он не передаётся, ТЗ п. 4).
3. Указать папку и имя, например `УПКБ-6 разработка`.
4. Сразу сделать **архивную копию папки проекта**. Дальше — копия перед каждым крупным шагом.

**Как проверить:** проект открылся, дерево слева содержит пустые разделы.

## О-2. Создать группу библиотеки и библиотечный элемент

1. В дереве проекта найти раздел **`Библиотеки`** (узел дерева `IncludedLibraries`, подпись подтверждена).
2. Правый клик на разделе → `Добавить` (?) → `Группа` (?). Имя группы: **`УПКБ-6`**.
3. Правый клик на группе `УПКБ-6` → `Добавить` (?) → `Библиотечный элемент` (?) (пользовательский элемент).
4. Имя элемента — рабочее, по таблице:

| ПБЭ | Имя элемента |
|---|---|
| № 1 | `ПБЭ-1 Приточная Carel` |
| № 2 | `ПБЭ-2 Парная вытяжная Schneider` |
| № 3 | `ПБЭ-3 Заготовка ШУВ-К` |
| № 4 | `ПБЭ-4 Группа вытяжных без ПЛК` |
| № 5 | `ПБЭ-5 VRF LG-Electrolux-MDV` |
| № 6 | `ПБЭ-6 Вытяжная Carel µAria корп.8` |
| № 7 | `ПБЭ-7 Приточная Carel µAria корп.22` |
| № 8 | `ПБЭ-8 Вытяжная Zentec M245` |

5. Внутри элемента должно получиться дерево — **ровно как на рис. А.1 Примера ПБЭ**:

```
<Элемент>
└── Ресурсы
    ├── Программы
    ├── Сообщения
    └── Окна
```

**Как проверить:** три папки внутри `Ресурсы`, элемент лежит в `Библиотеки`, а **не** в `Объекты`.

**Иконки левой панели — как на рис. А.1 Примера ПБЭ.** В образце дерево элемента `АОВ` выглядит так (слева — иконка, справа — служебные маркеры):

| Иконка в документах | Как выглядит в среде (рис. А.1) | Узел | Что это |
|---|---|---|---|
| элемент | **красноватый квадрат с белой пиктограммой схемы** (три связанных блока) | `АОВ` / `<Элемент>` | сам библиотечный элемент |
| папка | **серая папка с корешком** | `Ресурсы`, `Программы`, `Сообщения`, `Окна` | папки ресурсов элемента |
| окно | **оранжевый квадрат с белой сеткой 2×2** | `Строка`, `Мнемосхема`, `Температуры`, `Настройки`, `Планировщик` … | окно ПБЭ |
| ➡️ | **красноватый квадрат с белой стрелкой** в скобку | `Название`, `Обозначение`, `Включена`, `СостояниеУст` … | параметр типа |

**Служебные маркеры справа от узла** (в образце они есть не у всех узлов):

| Маркер | Что означает | Где стоит в образце |
|---|---|---|
| архив | параметр **архивируется** | у всех параметров образца |
| тренд | параметр выводится **в тренд** | только у `Состояние`, `Прогрев`, `ЛетнийРежим` — вместе с архивированием |
| переход | на узел есть **переход** (окно открывается действием) | у шести окон: `Температуры`, `Общая диаграмма`, `Производительность вентиляторов`, `Дискретные значения`, `Настройки`, `Планировщик` |

**Так выглядит образец (рис. А.1 Примера ПБЭ)** — сверяйте своё дерево с ним:

```text
АОВ                                   ← библиотечный элемент
├── Ресурсы
│   ├── Программы                     ← ST-программа
│   ├── Сообщения                     ← ресурсы сообщений
│   └── Окна
│       ├── Строка
│       ├── Мнемосхема
│       ├── Температуры                    
│       ├── Общая диаграмма                
│       ├── Производительность вентиляторов 
│       ├── Дискретные значения            
│       ├── Настройки                      
│       ├── Планировщик                    
│       └── Термостат 1
└── ➡️ параметры верхнего уровня
    ├── ➡️ Название          
    ├── ➡️ Обозначение       
    ├── ➡️ Включена          
    ├── ➡️ Отключена         
    ├── ➡️ СостояниеУст      
    ├── ➡️ ЗапускУспешен     
    ├── ➡️ Прогрев           
    ├── ➡️ ПрогревПрошло     
    ├── ➡️ ЛетнийРежим       
    ├── ➡️ Блокировка        
    ├── ➡️ ОбщаяАвария       
    └── ➡️ Авария            
```

> Эмодзи в документах — текстовый эквивалент иконок рис. А.1: в среде ищите **красный квадрат со схемой** (элемент), **серые папки** (`Ресурсы`, `Программы`, `Сообщения`, `Окна`), **оранжевые квадраты с сеткой** (окна) и **красные квадраты со стрелкой** (параметры).

> Правило: **элемент создаётся в `Библиотеки`**, а **экземпляр — в `Объекты`** (это узлы дерева проекта, над элементом). Если элемент случайно создан в `Объекты`, он не попадёт в библиотеку и `.mslb` не соберётся — это самая частая ошибка на шаге 1.

## О-3. Создать параметр

1. Выделить **элемент** (или ту ветку, где должен лежать параметр — у ПБЭ все параметры на верхнем уровне элемента, факт F-2).
2. Правый клик → `Добавить` (?) → `Параметр` (в части сборок пункт называется `Переменная`; обе подписи есть в реестрах сборки).
3. В открывшейся строке/окне свойств задать: **имя** (ровно как в `параметры.md`, кириллица и регистр должны совпадать посимвольно) и **тип**.
4. Типы — из таблицы параметров: `BOOL`, `INT`, `DINT`, `REAL`, `STRING`, `TIME`.
5. Направление задаётся назначением параметра, а не отдельной кнопкой:
   * **`Настр`** — параметр-настройка: значение задаётся в экземпляре (например `Обозначение`, `Корпус`, `НастрЕстьЗаслонка1`);
   * **`Вх`** — приём из канала: параметр подключает ДИГАМ к тегу;
   * **`Вых`** — значение, которое формирует ПБЭ (команды);
   * **`Выч`** — считается программой элемента.

> **Главное правило:** имена параметров берутся **только** из `параметры.md`. Любое расхождение в букве (например `СостояниеТекст1` вместо `Состояние1Текст`) даёт ошибку компиляции «неизвестный идентификатор».

### О-3.1. Быстрое создание индексных семейств
Там, где параметры повторяются по индексу (`N = 1…5`, `Вн01…Вн66`, `Нар01…Нар07`):
1. Создать **полный набор для первого индекса** (`1` или `01`) — по таблице.
2. Выделить весь набор → `Копировать` (?) → `Вставить` (?).
3. В копии заменить индекс в именах (`1` → `2`, `01` → `02`).
4. **Обязательно перепроверить связи** в копиях: типовая ошибка — копия блока 3 продолжает читать параметры блока 1 (тест на независимость падает).

## О-4. Настроить конвертер параметра

Конвертер задаёт, **как значение выглядит на экране** (текст и цвета). Настраивается на параметре типа.

1. Выделить параметр → панель **`Свойства`** (в справке — «Панель свойств») → раздел **`Конвертация`** (подпись подтверждена).
2. Добавить строки по таблице из `параметры.md` соответствующего ПБЭ (§ «Конвертеры»).
3. В каждой строке заполнить: **значение**, **текст**, **цвет заливки**, **цвет текста**.

**Три требования ТЗ с жёстким контролем:**

| Требование | Как выполняется |
|---|---|
| C-8 — цвета конвертеров | заливка **только** `rgb(240,240,240)`, `rgb(0,176,80)`, `rgb(255,192,0)`, `rgb(255,0,0)`, `rgb(128,128,128)`. **Не** `#00B050` |
| C-9 — `False` первой | в любом булевом конвертере **первая строка — `False`**, вторая — `True`. Перепутано — «Норма» и «Авария» поменяются местами |
| Цвет текста | **`#RRGGBB`** (`#202020`, `#FFFFFF`) — с решёткой, это отдельное свойство |

## О-5. Создать окно и разместить графику

1. Выделить папку **`Ресурсы → Окна`** → правый клик → `Добавить` (?) → `Окно` (?).
2. Имя — **дословно по Перечню ПБЭ** (например `Мнемосхема установки`). Ошибка в имени = провал приёмки по п. C-1.
3. Задать размер (ориентиры — в `сборка.md` каждого ПБЭ).
4. Разместить объекты из таблицы `окна_и_связи.md` §«состав окна»: **текст**, **примитив/индикатор**, **изображение**, **группа**, **кнопка**, **поле ввода**, **селектор**.
5. Имена объектов — по схеме **`<Окно>_<Группа>_<Поле>`** либо `<№> <День> <№> <Что>` для планировщика (правило O-14 каркаса окон).

### О-5.1. Связать объект с параметром
1. Выделить объект → панель `Свойства`.
2. Выбрать свойство: **`Текст`**, **`Заливка`**, **`Значение`**, **`Видимость`** — по таблице связей.
3. У свойства два раздела: **`Входящая связь`** (параметр → объект) и **`Исходящая связь`** (объект → параметр) — подписи подтверждены.
4. Задать связь, выбрав параметр по полному имени: **`Библиотеки.Локальная.Объекты.<Элемент>.<Параметр>`** (факт F-18).
5. Формат отображения пишется в свойстве текста: `{f1} °C`, `{f1} %` (факт F-15).

> **Правило ТЗ C-11 «пишет ⇒ читает»:** у каждого поля ввода и селектора должны быть заполнены **обе** секции — `Входящие связи` **и** `Исходящие связи` — на свой параметр, и включён флажок **«Использовать вход…»** (рис. А.4, А.5).

### О-5.2. Поля ввода: обязательные свойства
Для каждого поля ввода задать: **`Минимум`**, **`Максимум`**, **`Шаг инкремента = 1`**, **`Текущее значение`**, при необходимости **`Макс кол-во знаков после запятой`** (подписи подтверждены по реестру свойств; `Минимум`/`Максимум`/`Текущее значение` — рис. А.5).

### О-5.3. Селектор (выбор из списка)
Список значений задаётся строкой с разделителем **`~`**: например `Приток~Помещение` (факт F-14).

### О-5.4. Скрытие группы по настройке экземпляра
1. Выделить **группу** (не отдельный объект).
2. Свойство **`Видимость`** → задать **входящую связь** на соответствующий параметр `Настр…` (рис. А.3).
3. При необходимости включить флажок **«Скрывать при отсутствии…»**.

> Частая ошибка: связь ставят на «Активность» вместо «Видимости» — группа видна всегда.

## О-6. Кнопки: только через действие по событию

Требование ТЗ C-10: команда формируется **действием по событию**, а не прямой связью.

1. Выделить кнопку → панель `Свойства` → раздел **`События`** (подпись подтверждена; в образце — «действие» элемента).
2. Выбрать событие нажатия (`Click` (?)).
3. Выбрать действие:

| Что делает кнопка | Действие | Куда |
|---|---|---|
| Команда (СТОП, СТАРТ, СБРОС, сброс зуммера) | **`Установить параметр`** (`SetParameter`) — подпись подтверждена | параметр-команда ПБЭ, значение `TRUE`/`FALSE` |
| Переход к другому окну | **`Открыть окно`** (`Action.OpenDialog`) — подпись подтверждена | имя окна |
| Открыть журнал сообщений | **`Открыть окно`** | окно журнала |

4. Подпись кнопки — по `окна_и_связи.md` (СТОП, СТАРТ, СБРОС, `РАСПИСАНИЕ`, `ОТКРЫТЬ ЖУРНАЛ СООБЩЕНИЙ`).

> **Кнопки `РАСПИСАНИЕ` не должно быть** у ПБЭ № 2, № 4 и № 3 (ТЗ п. 3.1). Проверяется тестами T2-09, T3-09, T4-24.

## О-7. Создать программу ST и вставить код

1. `Ресурсы → Программы` → правый клик → `Добавить` (?) → `Программа` (?).
2. Имя — **ровно** `Программа_ST_1`, язык — **ST**.
3. Открыть файл `NN_ПБЭ_XX/st/Программа_ST_1.st`, выделить **всё** (`Ctrl+A`), скопировать, вставить в редактор программы.
4. Нажать **кнопку компиляции** (?) (обычно значок «галочка»; подпись кнопки не подтверждена). Вкладка в среде называется **`Компиляция`** (подпись подтверждена).

**Правило вставки:** вставлять файл **целиком**. Построчная вставка обрывает `VAR … END_VAR` и даёт «неизвестный идентификатор `i`».

**Что делать с ошибками компиляции** — таблица в `сборка.md` каждого ПБЭ (§ «Возможные ошибки компиляции») и в конце настоящего документа.

## О-8. Создать сообщение

1. `Ресурсы → Сообщения` → правый клик → `Добавить` (?) → `Сообщение` (?).
2. Имя — по таблице сообщений в `параметры.md` (имена первых сообщений совпадают с именами параметров рис. А.6 — это воспроизведение образца).
3. Заполнить свойства (структура из 9 элементов, рис. А.6):

| Элемент | Значение |
|---|---|
| **Тип значения** | **BOOL** |
| **Отношения** | **«Прием значения из»** (подпись подтверждена) |
| **Активность** | **входящая связь** на параметр-признак (например `Пожар`) |
| **Сообщение** | текст сообщения (можно с подстановкой обозначения) |
| **Приоритет** | по таблице сообщений `параметры.md` |
| Время активации / деактивации / квитированности / изменения | служебные, заполняются средой |
| **Комментарий** | свободный текст |

4. Архивирование сообщения — флажок **`Архивировать`** + выбор **`Шаблон архивирования`** (обе подписи подтверждены).

## О-9. Настроить архивирование параметра

1. Выделить параметр → `Свойства` → признак **`Архивировать`** (в редакциях — `Historizing`) → включить.
2. Выбрать **шаблон архивирования**.
3. Состав архивных параметров — таблица «Архивирование» в `параметры.md` каждого ПБЭ.

> У ПБЭ № 4 **ни один** параметр не архивируется (ТЗ прил. 1 ч. 2), у ПБЭ № 3 — только отображаемые значения.

## О-10. Настроить тренд (окно-тренд)

1. Создать окно с именем по Перечню (`Температуры`, `Общая диаграмма`, `Производительность вентиляторов`, `Дискретные значения`).
2. Разместить **компонент-тренд** (?) (тип окна на базе `MasterSCADA.View.*`, методы `AddPenMethod` / `RemovePenMethod` — факт из проверенного API).
3. Добавить **перья** по таблице «Тренды — состав сигналов» в `параметры.md`, связав каждое перо с параметром.
4. Формат оси/чисел — по таблице «Форматы отображения».

## О-11. Создать экземпляр и задать настройки

1. В дереве проекта перейти в раздел **`Объекты`** (?) (рабочая часть проекта, не библиотека).
2. Правый клик → `Добавить` (?) → `Экземпляр` (?) → выбрать нужный библиотечный элемент из группы `УПКБ-6`.
3. Задать настройки (значения — в `сборка.md` и `паспорт.md` соответствующего ПБЭ): `Обозначение`, `Название`, `Корпус`, `Помещение…`, флаги `НастрЕсть…`.
4. Открыть окна экземпляра, проверить, что значения подставляются.

> **Проверка ТЗ п. 1.2:** открытие окна **не создаёт** новый экземпляр. Число экземпляров задаётся в Перечне (52 + 3 тестовых = 55).

## О-12. Скопировать элемент (когда ПБЭ строится из донора)

1. Правый клик на элементе-доноре в `Библиотеки → УПКБ-6` → `Копировать` (?).
2. Правый клик на группе → `Вставить` (?).
3. Переименовать копию в имя из таблицы `О-2`.

# Блок 4. Типовые ошибки (сведены из всех восьми инструкций)

| Симптом | Причина | Что делать |
|---|---|---|
| «Неизвестный идентификатор `<Имя>`» | параметр не создан или назван иначе | сверить с `параметры.md` посимвольно |

| Норма и авария перепутаны | `True` стоит первой строкой | `False` — первой |
