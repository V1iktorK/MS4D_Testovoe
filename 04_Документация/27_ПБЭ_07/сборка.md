# ПБЭ № 7. Инструкция по сборке в MasterSCADA 4D 1.3.10.34633

**Кто выполняет:** пользователь. Материал — этот документ плюс `параметры.md`, `окна_и_связи.md`, `st/Программа_ST_1.st`, а также `21_ПБЭ_01/планировщик.md`.
**Что получится:** библиотечный элемент приточной установки Carel µAria с 13 окнами и планировщиком.
**Оценка времени:** ≈ 23,5 ч.

> **Главный принцип.** ПБЭ № 7 — **не разработка с нуля, а копия варианта µAria ПБЭ № 1**. ТЗ прямо это предписывает: «Состав параметров и функций — как у варианта Carel µAria ПБЭ № 1». Поэтому основная работа — **копирование и три точечных правки**, а не создание заново.

## Шаг 2. Копирование элемента (20 мин)

1. В разделе `Библиотеки → УПКБ-6` **скопировать** элемент `ПБЭ-1 …Carel…` → вставить.
2. Переименовать копию: **`ПБЭ-7 Приточная Carel µAria корп.22`**.
3. Убедиться, что скопировались: параметры, `Ресурсы → Программы`, `Ресурсы → Сообщения`, `Ресурсы → Окна` (все 13).

---

> **Внимание.** **Три параметра времени обязательны (уточнение по среде).**
> Проверено: функции получения текущего времени в MasterSCADA 4D 1.3.10.34633 **НЕТ** (`GET_LOCAL_TIME` отсутствует).
> Поэтому планировщик **принимает** день недели и время суток извне:
> * `СистемаДеньНеделиТекст` (STRING, **Вх**) — `Пн` … `Вс`;
> * `СистемаЧас` (INT, **Вх**) — 0…23;
> * `СистемаМин` (INT, **Вх**) — 0…59.
>
> При сборке копированием эти параметры **переносятся вместе с элементом** — их не нужно создавать заново. Но их **надо подключить к системному тегу времени**: в тестовом проекте это делаете вы, в рабочем проекте ДИГАМ. **Проверка:** при работающем планировщике `ТекущийИнтервал` меняется по часам суток.
>
> **Если системного тега времени в проекте нет** — сообщите мне: потребуется отдельная программа формирования дня недели и времени в проекте ДИГАМ. Логика ПБЭ при этом **не изменится** (параметры останутся теми же, изменится только источник).

## Шаг 4. Правка № 2 — удалить разбор масок (1,5 ч)

### 4.1. Удалить параметры

| Удалить | Почему |
|---|---|
| `АварияКрит1` (DINT) | масок нет |
| `АварияПредуп1` (DINT) | масок нет |
| `ВариантАварий` | разбирать нечего |
| `НастрРазборМаски` | разбор не выполняется |
| `ВариантОборудования` | один контроллер |

### 4.2. Изменить направление аварийных признаков (ключевое!)

Семь параметров в ПБЭ № 1 были **вычисляемыми** (результат `GetBit`). В ПБЭ № 7 они должны быть **входными** — от канала:

| Параметр | Было | Стало |
|---|---|---|
| `Пожар` | Выч | **Вх** |
| `АвЗаслВыт` | Выч | **Вх** |
| `АвЗаслПрит` | Выч | **Вх** |
| `АвПолохЗаслРецВыт` | Выч | **Вх** |
| `АвПолохЗаслРецПрит` | Выч | **Вх** |
| `НизкаяТПомещения` | Выч | **Вх** |
| `ОбрывТПомещения` | Выч | **Вх** |

> **Внимание.** **Это самая важная правка.** Если оставить их вычисляемыми без разбора, они всегда будут FALSE — аварии не будут видны. Тест **T7-18**.

### 4.3. Правка кода
В программе:
* удалить **раздел 0** («выбор варианта оборудования»);
* удалить **раздел 2** («разбор битовых масок») целиком — там 17 вызовов `GetBit`;
* удалить из блока `VAR` переменные `i`, `n`, `k`;
* заменить строку `КолАварий.Value := n + КритОтд;` на `КолАварий.Value := КритОтд;`;
* заменить блок формирования `КодАварии` (был «младший бит маски или 100») на простую форму: `1` при наличии, `-1` при отсутствии.

**Проще:** взять программу из `st/Программа_ST_1.st` этого ПБЭ — она уже без разбора масок.

### 4.4. Убрать отображение масок
Проверить, нет ли в окнах полей, показывающих `АварияКрит1` или состояние разбора. Если есть — удалить.

**Проверка шага:** T7-08, T7-18.

## Что даёт этот ПБЭ остальным

После проверки ПБЭ № 7 у вас есть **два подтверждённых «донора»**:
* **ПБЭ № 1** — донор для **приточных** ПБЭ (№ 6 — вытяжка, но с общим каркасом планировщика и таблиц);
* **ПБЭ № 7** — донор для **µAria**-ПБЭ: в нём уже нет разбора масок, что делает его удобнее для **ПБЭ № 6** (Carel µAria, вытяжка корпуса 8).
