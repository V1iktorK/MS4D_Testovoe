Направление: **Вх** — приём из канала; **Вых** — формируется ПБЭ; **Настр** — настройка экземпляра; **Выч** — вычисляемое в ПБЭ.

> **Основание состава.** ПБЭ № 6 — вытяжная установка на Carel µAria. Состав заимствован у ПБЭ № 7 (вариант µAria), из которого **удалены приточные узлы** (калорифер, ККБ, насос, влажность) и **добавлены три механизма** по требованиям ТЗ прил. 1 ч. 2:
> * **групповые параметры** (общий шкаф управления) — §2;
> * **задержки тревог** — §9;
> * **индикация основной и резервной работы** — §10.
>
> **Итого 291 параметр.**

### 6.1. Сезон: как формируется `ТекущийСезон`

**Требование ТЗ:** сезон (зима/лето) задаётся оператором либо определяется автоматически по температуре наружного воздуха.

| Параметр | Роль |
|---|---|
| `ЗаданиеСезона` (INT) | Команда-селектор в окне: **0 Зима, 1 Лето, 2 Авто** |
| `ТПереходаЛето` (REAL, 0…30 °C) | Верхний порог: при `ТНарВозд >= ТПереходаЛето` устанавливается **Лето** |
| `ТПереходаЗима` (REAL, −30…10 °C) | Нижний порог: при `ТНарВозд <= ТПереходаЗима` устанавливается **Зима** |
| `ТНарВозд` (REAL) | Температура наружного воздуха |
| `АвДатчикТНарВозд` (BOOL) | Достоверность датчика наружного воздуха |
| `НастрЕстьТНарВозд` (BOOL) | Узел датчика наружного воздуха присутствует в составе |
| `ТекущийСезон` (STRING) | Результат: «Зима» или «Лето» — для окна и трендов |

**Алгоритм (раздел 11 программы):**

1. `ЗаданиеСезона` ограничивается диапазоном 0…2.
2. При `ЗаданиеСезона = 0` → «Зима»; при `= 1` → «Лето» — команда оператора имеет приоритет.
3. При `ЗаданиеСезона = 2` (Авто) и достоверном датчике сезон меняется **по гистерезису**:
   * если сейчас «Лето» — переход в «Зиму» только при `ТНарВозд <= ТПереходаЗима`;
   * если сейчас «Зима» — переход в «Лето» только при `ТНарВозд >= ТПереходаЛето`;
   * между порогами сезон **сохраняется**.
4. Если узел датчика отсутствует (`НастрЕстьТНарВозд = FALSE`) — автоматическое определение не выполняется, сезон остаётся прежним.

> **Зачем гистерезис.** Без него при температуре около порога сезон «дребезжал» бы при каждом изменении на 0,1 °C, а вместе с ним — сообщения и тренды. Два порога с зоной нечувствительности — штатное решение для сезонного переключения.

> **Начальное значение.** `ТекущийСезон` объявлен как **STRING** и хранит состояние между циклами программы, поэтому при сборке экземпляра ему задаётся начальное значение **«Зима»** (см. `сборка.md`, шаг настройки экземпляра). Если начальное значение не задать, до первого срабатывания порога параметр будет пустым.

## 22. Резервные параметры (объявлены, но ПБЭ не использует)

Параметры ниже присутствуют в перечне сигналов оборудования, поэтому объявлены в таблице,
но **не участвуют** ни в программе, ни в привязках окон, трендов и сообщений.
Они создаются «на будущее» либо не создаются вовсе — решение принимает сборщик.
Такие параметры отмечены как резервные — это не ошибка: ошибкой считается только
вычисляемый параметр, который программа не заполняет.

| Параметр | Почему не используется |
|---|---|
| `ДиагНетСвязиРекуператор` | Потеря связи с отдельным узлом. В ПБЭ выводится **сводный** `ДиагНетСвязи`; отдельные признаки заведены на будущее (детализация по узлам). |
| `КлапанВытЗакрыт` | Конечник / положение исполнительного механизма. Резерв под индикацию; в составе окон ПБЭ не отображается. |

| `НомРасходаПритока` | Номинальный расход (переток). Настройка для расчёта; текущая версия программы расчёт перетока не выполняет. |
| `ПожарОбщий` | Общий сигнал пожара отдельной точкой. Относится к системе противопожарной автоматики и в объём ПБЭ не входит. |
