# 02. Проверенный API MasterSCADA 4D 1.3.10

**Источник фактов:** локальная установка `C:\Program Files\MPSSoft\MasterSCADA 4D 1.3\bin` (редакция `1.3.10.36374` сборки ядра; среда по ТЗ — `1.3.10.34633`) и схема хранения проекта MasterSCADA (`Пример ПБЭ.fdb`, Firebird 2.5, `MasterSCADA.Project.HMI`).

Метод проверки: имена типов извлечены из системной таблицы `TYPES` проекта (817 типов), плюс реконструкция ST-кода по рисунку А.2 Примера ПБЭ.

> **Правило работы.** В ST-коде используются только те функции, которые перечислены в §2 ниже. Ничего «похожего по смыслу» не добавляется. Если для задачи функции в списке нет — задача решается арифметикой, `IF`/`CASE`/`FOR` или конвертером параметра.

## 2. Что можно вызывать в ST (проверенный перечень)

### 2.1 Битовые операции
`GetBit`, `SetBit`, `ROL`, `ROR`, `SHL`, `SHR`, `AND`, `OR`, `XOR`, `NOT`

### 2.2 Триггеры и таймеры (для задержек тревог, ротации, моточасов)
`R_TRIG`, `F_TRIG`, `TON`, `TOF`, `TP`, `RS`, `SR`, `CTU`, `CTD`, `CTUD`, `CTU_DINT`, `CTD_DINT`, `CTUD_DINT`

### 2.3 Арифметика и сравнение
`ADD`, `SUB`, `MUL`, `DIV`, `MOD`, `EXPT`, `ABS`, `SQRT`, `LN`, `LOG`, `EXP`, `SIN`, `COS`, `TAN`, `ASIN`, `ACOS`, `ATAN`, `MIN`, `MAX`, `LIMIT`, `ROUND`, `TRUNC`, `TRUNC_LINT`, `MOVE`, `SEL`, `MUX`, `EQ`, `NE`, `LT`, `LE`, `GT`, `GE`

### 2.4 Работа со строками (тексты аварий)
`CONCAT`, `JOIN_STRING`, `SPLIT_STRING`, `FIND`, `LEFT`, `RIGHT`, `MID`, `LEN`, `INSERT`, `DELETE`, `REPLACE`, `UPPERCASE`, `LOWERCASE`, `DINT_TO_STRING`, `INT_TO_STRING`, `REAL_TO_STRING`, `LREAL_TO_STRING`, `BOOL_TO_STRING`, `STRING_TO_DINT`, `STRING_TO_INT`, `STRING_TO_REAL`, `STRING_TO_BOOL`

### 2.5 Приведение типов (преобразование значений)
Полный набор `X_TO_Y` для типов `BOOL, SINT, USINT, BYTE, INT, UINT, WORD, DINT, UDINT, DWORD, LINT, ULINT, LWORD, REAL, LREAL, STRING, TIME, TOD, DATE, DT` — например `INT_TO_DINT`, `REAL_TO_INT`, `DINT_TO_REAL`, **`TIME_TO_INT`**, `DWORD_TO_REAL_BIT`, `REAL_TO_DWORD_BIT`, `LREAL_TO_LWORD_BIT`, `WORD_TO_HEX`, `DWORD_TO_HEX`, `BYTE_TO_STRING`, `STRING_TO_BYTE_ARRAY`.
>
> `TIME_TO_INT` **подтверждён пользователем** при проверке среды (`97_Итоговый_отчёт.md` §7.1, ответ № 6) и используется в ПБЭ № 6 и № 8 для пересчёта `TIME`-задержек в секунды.

### 2.6 Работа с `SYSTEM_*_PARAM` (обёртки каналов/параметров)
Есть явные преобразователи в обе стороны:
`SYSTEM_BOOL_PARAM_TO_BOOL` / `BOOL_TO_SYSTEM_BOOL_PARAM`, и аналогично для `BYTE, SINT, WORD, INT, DWORD, DINT, LINT, LWORD, REAL, LREAL, STRING, TIME, TOD, DATE, DT`.
**Применение:** когда надо записать результат разбора в другой параметр через функцию, а не прямым присваиванием `.Value`.

### 2.7 Время и дата
`GET_TIME`, `GET_LOCAL_TIME`, `GET_UTC_TIME`, `GET_TICKS`, `TIME_TO_TICKS`, `TICKS_TO_TIME`, `SPLIT_DT`, `SPLIT_DT_LOCAL`, `SPLIT_DATE`, `SPLIT_TOD`, `CONCAT_DT`, `CONCAT_DT_LOCAL`, `CONCAT_DATE_TOD`, `DT_TO_TOD`, `TOD_TO_TIME`, `DT_TO_STRING`, `DT_TO_STRING_LOCAL`, `ADD_DT_TIME`, `SUB_DT_DT`, `MULTIME`, `DIVTIME`
**Применение:** планировщик, моточасы, задержки тревог, вычисление «сейчас внутри интервала расписания».

### 2.8 Качество сигнала
`IS_GOOD`, `IS_BAD`, `IS_UNCERTAIN`

### 2.9 Прочее
`LOG_MESSAGE`, `OBJECT_TO_STRING`, `CREATE_ARRAY`, `RESIZE_ARRAY`, `LOWER_BOUND`, `UPPER_BOUND`, `CHECK_JSON_STRING`

## 3. Действия по событию (кнопки) — из перечня типов

Проверенные типы действий:
* `MasterSCADA.View.Action.SetParameter` — **запись значения в параметр** (основное действие кнопок СТАРТ/СТОП/СБРОС/СБРОС ЗУММЕРА и переключателей);
* `MasterSCADA.View.Action.OpenDialog` — открытие окна/всплывающего окна (кнопки «РАСПИСАНИЕ», «Настройки», «Диаграммы», переходы);
* `MasterSCADA.View.Action.CallEvent` — вызов события;
* `MasterSCADA.View.Event` + `MasterSCADA.View.EventParameters` — описание события элемента;
* `MasterSCADA.View.MouseEvent`, `MasterSCADA.View.KeyboardEvent`, `MasterSCADA.View.TableEvent`, `MasterSCADA.View.MarkerClickEvent`, `MasterSCADA.View.MapClickEvent` — событийные привязки для метки на плане и строки таблицы.

**Отсюда правило ТЗ** «команды кнопок — через действия по событию»: кнопка не пишет в тег напрямую, а на событие нажатия выполняет `Action.SetParameter`, записывающий значение в параметр-команду ПБЭ. И этот же параметр кнопка **читает** — по ТЗ «если элемент записывает значение, он должен также читать текущее».

## 4. Штатные шаблоны архивирования и расписаний

В библиотеке типов присутствуют:
`MasterSCADA.Library.StandardArchiveTemplates`, `MasterSCADA.ArchiveTemplate`, `MasterSCADA.System.Archive`, `MasterSCADA.System.EventsArchive`, `MasterSCADA.Var.Historizing`, `MasterSCADA.Var.Convertation`, `MasterSCADA.Var.Direction`, `MasterSCADA.Var.AccessType`, `MasterSCADA.Var.Increment`, `MasterSCADA.Var.IsInverse`, `MasterSCADA.Var.EdgeType`, `MasterSCADA.Library.StandardSchedules`.

**Вывод:** архивирование настраивается через свойства параметра (`Historizing` + шаблон), а не через отдельные «архивные» объекты элемента. Тренды — через `MasterSCADA.View.Method.AddPenMethod` / `RemovePenMethod` / `ExportMethod` / `SaveImageAsMethod` / `UpdateMethod` + `MasterSCADA.View.MethodParameters` — то есть штатные методы окна-тренда.

## 5. Чего в перечне НЕТ (чтобы не выдумывать)

* Нет встроенной функции «разбор маски в список текстов». Тексты аварий формируются вручную: `CASE`/`IF` + строковые функции §2.4.
* Нет типа «Планировщик» для окна элемента, применимого в 1.3.10 как готовый компонент. Планировщик по ТЗ п. 3.2 выполняется **графикой и параметрами** по образцу (ТЗ прямо требует «полный функционал планировщика по образцу» и «SCADA формирует команды через параметры экземпляра ПБЭ»).
* Нет функции «моточасы». Моточасы ПБЭ № 2 считаются арифметикой: приращение `TIME`-разности при работающем вентиляторе.
* Нет функции записи расписания во встроенные программы контроллеров — и ТЗ это прямо запрещает (п. 3.2).
