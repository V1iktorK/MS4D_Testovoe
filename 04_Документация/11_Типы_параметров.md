# 11. Типы параметров, конвертеры и преобразование значений

Документ фиксирует: **каким типом объявляется каждый класс параметров**, **как значения преобразуются** и **как настраиваются конвертеры**. Обязателен для всех 8 ПБЭ.

---

## 1. Обёртки параметров MasterSCADA 4D

Пара метр ПБЭ — это обёртка `SYSTEM_<ТИП>_PARAM` со структурой:

| Поле | Смысл |
|---|---|
| `Value` | собственно значение (именно к нему обращается ST: `Параметр.Value`) |
| `SourceTime` | метка времени источника |
| `StatusCode` | признак качества |

Подтверждено схемой проекта MasterSCADA (`Пример ПБЭ.fdb`, Firebird 2.5): типы `SYSTEM_LREAL_PARAM`, `SYSTEM_BOOL_PARAM`, `SYSTEM_DINT_PARAM`, `SYSTEM_STRING_PARAM`, `SYSTEM_SINT_PARAM`, `SYSTEM_DATE_PARAM`, `SYSTEM_TIME_PARAM`, `SYSTEM_TOD_PARAM`, `SYSTEM_DWORD_PARAM`, `SYSTEM_DT_PARAM`, `SYSTEM_LINT_PARAM`, `SYSTEM_WORD_PARAM` — каждый с полями `Value`, `SourceTime`, `StatusCode`.

Из этого следуют **три правила кода**:
1. В ST к параметру обращаются через `.Value`.
2. Для записи результата в **другой параметр** можно как прямое присваивание (`Пожар.Value := …`), так и функция-преобразователь `*_TO_SYSTEM_*_PARAM` — если типы не совпадают.
3. Качество сигнала проверяется функциями `IS_GOOD`, `IS_BAD`, `IS_UNCERTAIN` — используется для формирования `ДиагНетСвязи`.

## 2. Таблица «класс параметра → тип»

### 2.1. Команды и признаки

| Класс | Тип | Range / значения | Значение по умолчанию |
|---|---|---|---|
| Команда пуска/останова | BOOL | `FALSE`/`TRUE` | `FALSE` |
| Команда сброса аварии | BOOL | `FALSE`/`TRUE` | `FALSE` |
| Команда сброса зуммера (№ 8) | BOOL | `FALSE`/`TRUE` | `FALSE` |
| Признак аварии (отдельный) | BOOL | `FALSE`/`TRUE` | `FALSE` |
| Признак «есть авария» | BOOL | `FALSE`/`TRUE` | `FALSE` |
| Признак предупреждения | BOOL | `FALSE`/`TRUE` | `FALSE` |
| Выбор основного вентилятора | INT (перечисление) | `1` — основной В1, `2` — основной В2 | `1` |
| Режим / сезон | INT (перечисление) | см. §3 | по варианту |
| Состояние установки | INT (перечисление) | `0` Стоп, `1` Работа, `2` Предупреждение, `3` Авария, `4` Нет связи | `4` |
| Настройки состава узлов | BOOL | `FALSE`/`TRUE` | по варианту |

### 2.2. Маски аварий

| Класс | Тип | Правило |
|---|---|---|
| Слово критических аварий | **DINT** | ТЗ п. 3: «для масок, использующих в образце DINT, этот тип сохраняется». Подтверждено рис. А.2 (`АварияКрит1`) |
| Слово предупреждений | **DINT** | то же правило |
| Код первой аварии | INT | `-1` если аварий нет (рис. А.2) |
| Код первого предупреждения | INT | `-1` если нет |
| Счётчик установленных бит | INT | локальная переменная, не параметр |

> **Запрет.** Если производитель передаёт аварии **отдельными BOOL**, параметр-маска **не создаётся** и программа разбора **не разрабатывается** (ТЗ п. 3). Это касается:
> * Carel µAria — ПБЭ № 1 (вариант корпуса 8), ПБЭ № 6, ПБЭ № 7;
> * Schneider M172 — ПБЭ № 2;
> * Zentec M245 — ПБЭ № 8 (A001–A007 отдельными признаками);
> * ПБЭ № 4.

### 2.3. Аналоговые измерения

| Класс | Тип | Ед. | Диапазон |
|---|---|---|---|
| Температура | REAL | °C | −60…+150 |
| Влажность | REAL | % | 0…100 |
| Положение заслонки/клапана | REAL | % | 0…100 |
| Производительность вентилятора | REAL | % | 0…100 |
| Перепад давления на фильтре | REAL | Па | 0…1000 |
| Расход воздуха | REAL | м³/ч | 0…100000 |
| Ток/мощность | REAL | А/кВт | по узлу |

Причина REAL, а не INT: тренды образца (рис. 1.5) имеют непрерывную шкалу `0…100`, а ST-код рис. А.2 использует `INT` только для служебных переменных. Температуры и проценты в АСДУ — вещественные.

### 2.4. Уставки и задания

| Класс | Тип | Ед. | Диапазон | По умолчанию |
|---|---|---|---|---|
| Уставка температуры | REAL | °C | 5…40 | 20 |
| Задание температуры притока | REAL | °C | 5…40 | 20 |
| Задание скорости притока | INT | % | 0…100 | 50 |
| Задание скорости вытяжки | INT | % | 0…100 | 50 |
| Уставка влажности | REAL | % | 0…100 | 50 |
| Уставки границ сезона («при +5 °C», «при −15 °C», «при −35 °C») | REAL | °C | −40…+20 | по рис. 1.3 |

Диапазон «0…100» и значение «50» по умолчанию — прямо из рис. А.5 (`Минимум 0`, `Максимум 100`, `Текущее значение 50`) и рис. 1.3 (все поля показывают `50`).

## 3. Перечисления: состав значений

Состав задаётся через свойство `ValuesList` параметра (рис. А.4: строка `Приток~Помещение`, разделитель `~`).

| Перечисление | Значения (код → текст) |
|---|---|
| Режим установки | `0` Авто, `1` Ручной, `2` Стоп |
| Сезон | `0` Зима, `1` Лето, `2` Переход |
| Нагрев/охлаждение (µAria) | `0` Нагрев, `1` Охлаждение, `2` Авто |
| Режим расписания | `0` Рабочий день, `1` Выходной, `2` Праздник, `3` Дежурный |
| Состояние установки | `0` Стоп, `1` Работа, `2` Предупреждение, `3` Авария, `4` Нет связи |
| Основной вентилятор (№ 2) | `1` Вентилятор 1, `2` Вентилятор 2, `3` Автоматическая ротация |
| Режим VRF-блока (№ 5) | `0` Авто, `1` Охлаждение, `2` Нагрев, `3` Вентиляция, `4` Осушение |
| Скорость вентилятора VRF (№ 5) | `0` Авто, `1` Низкая, `2` Средняя, `3` Высокая |
| Включение VRF-блока (№ 5) | `0` Выкл, `1` Вкл |
| Контроль активации пароувлажнителя | `0` По влажности, `1` По команде, `2` Отключён |
| Тип рекуператора | `0` Пластинчатый, `1` Роторный, `2` Нет |
| Уставка регулирования | `0` По притоку, `1` По вытяжке, `2` По помещению |

> Состав значений в §3 — вывод из смысла панелей рис. 1.1 и 1.3 (`Задание сезона`, `Уставка регулирования`, `Режим`, `Ход активации`, `Выбор основного приточного/вытяжного вентилятора`). Это допущение `D-63`; корректируется текстом в `ValuesList` без изменения программы.

## 4. Преобразование значений (что и где преобразуется)

| Что преобразуется | Откуда → Куда | Как |
|---|---|---|
| Аварийное слово → биты | DINT → BOOL | `GetBit(IN := АварияКрит1.Value, N := i)` (рис. А.2) |
| Биты → аварийное слово (сборка) | BOOL → DINT | `SetBit(IN := …, N := i)` |
| Число установленных бит | DINT → INT | цикл `FOR i := 0 TO 8 DO IF GetBit(…) THEN n := n + 1; END_IF; END_FOR;` |
| Код первой аварии | INT, `-1` при отсутствии | `k := -1; … IF k < 0 THEN k := i; END_IF;` |
| Наличие аварии | INT → BOOL | `ЕстьАвария.Value := n > 0;` |
| Скорость % → расход м³/ч | REAL → REAL | умножение на номинальный расход (параметр настройки) |
| Положение заслонки % → «открыта/закрыта» | REAL → BOOL | сравнение с порогами (параметры настройки) |
| Моточасы: накопление | TIME → INT (ч) | приращение времени при работающем узле |
| Температура для строки/тренда | REAL → STRING (для текста) | `REAL_TO_STRING`, формат `{f1}` (рис. 1.2: `{f1} %`) |
| Формирование текста аварии | INT (код) → STRING | `CASE`/`IF` + конкатенация строк |
| Дата/время расписания | DT → TOD | `DT_TO_TOD` / `SPLIT_DT` (см. §5) |
| Качество сигнала | `StatusCode` → BOOL | `IS_BAD` / `IS_GOOD` |
| Диапазон | REAL → REAL | `LIMIT` |

**Правило:** любое преобразование, которое видно в графике, оформляется либо конвертером параметра (§5 ниже), либо программой ST — **но не в связях окна**. Связь окна только передаёт значение.

## 5. Настройка конвертеров — пошагово

### 5.1. Булев конвертер (обязательный порядок)
1. Открыть свойства параметра → `Конвертация` (`MasterSCADA.Var.Convertation`).
2. Тип — булев (две строки).
3. Заполнить **первой** строку со значением `False`:
   * `Значение` = `False`
   * `Текст` = `Норма`
   * `Цвет` = `rgb(240,240,240)`
4. Второй строкой — `True`:
   * `Значение` = `True`
   * `Текст` = `Авария`
   * `Цвет` = `rgb(255,0,0)`
5. Цвет текста (отдельное свойство графики, не конвертера) — `#RRGGBB`, например `#202020`.

> **Проверка K-2:** если открыть конвертер и первая строка не `False` — требование ТЗ нарушено.

### 5.2. Аналоговый конвертер
1. Тип — диапазонный/табличный.
2. Строки заполняются **по возрастанию** условия (см. `10_Общие_соглашения.md` §5.3).
3. Каждая строка: `Условие`, `Текст`, `Цвет` — цвет строго `rgb(r,g,b)`.

### 5.3. Дискретный конвертер
1. Строки — по возрастанию кода значения, начиная с `0`.
2. Палитра — из `10_Общие_соглашения.md` §5.4.

### 5.4. Что категорически нельзя
* Писать `#RRGGBB` в конвертере (только `rgb(...)`).
* Ставить `True` раньше `False` в булевом конвертере.
* Задавать преобразование в связях окна вместо конвертера или программы.

## 6. Шкалы и формат отображения

| Класс | Формат | Источник |
|---|---|---|
| Температура | `{f1}` + ` °C` | рис. 1.2 |
| Влажность | `{f1}` + ` %` | рис. 1.2 |
| Скорость/положение | `{f1}` + ` %` | рис. 1.2 (`{f1} %`) |
| Расход | `{f0}` + ` м³/ч` | рис. 1.6 (легенда «м³/ч Общий расход») |
| Моточасы | `{f0}` + ` ч` | ТЗ прил. 1 ч. 2 |
| Время | `{hh}:{mm}` | рис. 1.4 |
| Строка/код | без формата | рис. А.4 |

## 7. Сводка жёстких правил (переносится в чек-лист каждого ПБЭ)

| Код | Правило |
|---|---|
| T-1 | Маски аварий — **DINT** |
| T-2 | Отдельные BOOL-аварии ⇒ маски и разбора **нет** |
| T-3 | Цвета конвертеров — **`rgb(...)`** |
| T-4 | `False` в булевом конвертере — **первая строка** |
| T-5 | Цвет текста — `#RRGGBB` |
| T-6 | Код аварии/предупреждения = `-1` при отсутствии |
| T-7 | Пишущий элемент читает текущее значение |
| T-8 | Команды — действиями по событию |
| T-9 | Обозначение и помещения видны при потере связи |
| T-10 | Отключённая функция не формирует команду |
| T-11 | Связь окна ничего не преобразует — только передаёт |
| T-12 | `LIMIT` используется для ограничения вводимых уставок |
