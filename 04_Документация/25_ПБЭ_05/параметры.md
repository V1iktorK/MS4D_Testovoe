# ПБЭ № 5. Таблица параметров

Направление: **Вх** — приём из канала; **Вх+Вых** — пишется оператором и читается для отображения; **Вых** — формируется ПБЭ; **Настр** — настройка экземпляра; **Выч** — вычисляемое в ПБЭ.

> **Схема индексов.** Параметры блоков создаются с суффиксом индекса:
> * `Нар<NN>` — наружный блок, `NN` = **01…20**;
> * `Вн<NN>` — внутренний блок, `NN` = **01…66**.
>
> Число применяемых блоков задаётся настройками `КолНаружныхБлоков` и `КолВнутреннихБлоков`; неприменённые индексы **скрываются** (признак `Применен`). См. `паспорт.md` §5.
>
> **Объём одного экземпляра: ≈ 560 параметров** (MDV, 66 внутренних блоков) — рекордный для комплекта. Проверка предела в среде — `сборка.md` шаг 0.

Команды, поданные с этих элементов, относятся к выбранному блоку (записываются обратно в `Вн<NN>…` программой).

| 3 | `Вн<NN>ТПомещения` | REAL | Вх | −60…150 °C | **температура помещения** |

### 5.3. Формирование значений для записи (4 шт. на блок)

ТЗ: «обработка данных, **включая формирование значений для записи**, определяются вариантом оборудования».

| № | Параметр | Тип | Напр. | Описание |
|---|---|---|---|---|
| 1 | `Вн<NN>ВключениеЗапись` | INT | Выч | Значение для записи в шлюз (0/1) |
| 2 | `Вн<NN>РежимЗапись` | INT | Выч | Код режима для шлюза |
| 3 | `Вн<NN>ВентиляторЗапись` | INT | Выч | Код скорости для шлюза |
| 4 | `Вн<NN>УставкаЗапись` | REAL | Выч | Уставка для шлюза (например в 0,1 °C) |

> **Смысл.** В ПБЭ команды хранятся в **универсальном виде** (§5.2). Шлюзы LG, Electrolux и MDV могут принимать иные коды. Программа преобразует универсальное значение в код производителя по таблице. Коды производителей не переданы (допущение `D-91`), поэтому таблица заполнена единообразными значениями и правится без изменения логики.

## 6. (?) Сокращение числа параметров (ключевое решение)

### 6.1. Проблема

Расчёт §4–§5 даёт:

| Составляющая | 66 индексов × параметров | Итого |
|---|---|---|
| Наружные блоки (20 индексов × 11) | — | 220 |
| Внутренние блоки: реквизиты (4 × 66) | 264 | |
| Внутренние блоки: данные (7 × 66) | 462 | |
| Внутренние блоки: запись (4 × 66) | 264 | |
| Внутренние блоки: текст (2 × 66) | 132 | |
| Прочие (§1–§3, включая §3.1) | — | 45 |
| **ИТОГО** | | **≈ 1387** |

**Это неприемлемо много** даже без учёта предела среды.

### 6.2. Принятое сокращение

| Что сокращается | Как | Экономия |
|---|---|---|
| **Текст состояния блока** (`РежимТекст`, `ВентиляторТекст`) | **Не создаётся.** Текст формирует **конвертер** параметра `Режим` / `Вентилятор` — это штатный механизм MasterSCADA, дублирования параметрами не нужно | **132** |
| **Значения для записи** (`*Запись`) | **Не создаются как отдельные параметры.** Преобразование выполняется в **программе** и записывается сразу в параметр-приёмник канала (`Вн<NN>РежимКанал` — только 2 параметра на блок: режим и вентилятор) | **132** |
| **Реквизит `ПомещениеНазначение`** | Назначение помещения берётся **из справочника** по номеру помещения; отдельный параметр не создаётся | **66** |
| **Наружные блоки: 20 индексов** | Сокращено до **7 индексов** (максимум по Перечню — 7 наружных у LG и MDV) | **143** |

### 6.3. Итоговый состав после сокращения

| Составляющая | На блок | Индексов | Итого |
|---|---|---|---|
| **Наружные блоки** — реквизиты (2) + данные (8) | 10 | **7** | **70** |
| **Внутренние блоки** — реквизиты (3) + данные (7) + канал записи (2) | 12 | **66** | **792** |
| Общие, состояния, выбранный блок (§1–§3, включая §3.1) | — | — | **41** |
| **ИТОГО** | | | **≈ 903** |

> **Проверьте:** даже после сокращения **903 параметра** — это **втрое** больше любого другого ПБЭ комплекта (у ПБЭ № 1 ≈ 306).
>
> **Вывод, который нужно озвучить ДИГАМ:** ПБЭ № 5 по конструкции принципиально отличается от остальных. Требование «для каждого блока внутри экземпляра — собственные параметры» при 66 блоках даёт объём, который **может превысить предел версии**. Это **не ошибка разработки, а следствие конструкции ТЗ**, и решается оно одним из двух способов:
> * **сократить число внутренних блоков в одном экземпляре** (например, разбить MDV на 2 экземпляра по 33 блока — но это меняет границу экземпляра, заданную Перечнем);
> * **согласовать запасной вариант B** из `паспорт.md` §5.4 (два набора по 33 индекса, тип остаётся один).

## 10. Сообщения

Тип значения **BOOL**, активность входящей связью, 9 внутренних элементов (рис. А.6).

> **Важно: сообщения на каждый блок не создаются.** При 66 блоках это дало бы сотни сообщений на один экземпляр. Вместо этого создаются **сводные** сообщения уровня системы:

| Сообщение | Параметр | Приоритет |
|---|---|---|
| `Авария блока VRF` | `ЕстьАвария` | Высокий |
| `Нет связи со шлюзом VRF` | `ДиагНетСвязи` | Высокий |
| `Авария наружного блока` | `Нар<01>Ошибка` … `Нар<07>Ошибка` (ИЛИ) | Высокий |
| `Предупреждение VRF` | `ЕстьПредупр` | Низкий |

**Текст аварии** формируется параметром `КодАварииТекст` — он содержит **обозначение блока**, у которого авария. Так оператор видит, **какой именно** блок требует внимания, без сотен отдельных сообщений.

> **Внимание.** **Если ДИГАМ потребует сообщение на каждый блок** — это 66 × 2 (ошибка и защита) = **132 сообщения** на экземпляр. Это технически возможно, но требует согласования по нагрузке на журнал. Вынесено в `сборка.md` шаг 11.

## 12. (?) Согласование объёма: индексная схема и разрешение 66 блоков

### 12.1. Противоречие, которое нужно снять

Расчёт §4–§6 и схема индексов дают **66 индексов внутренних блоков**. Но **копирование выбранного блока** в ST-программе требует явного блока `IF Инд = N` **на каждый индекс** (см. `st/Программа_ST_1.st` §4 и §5). Для 66 индексов это 66 × 2 веток по 7 присваиваний — ≈ **924 строки** только на одно копирование.

**Это не техническая невозможность, а вопрос объёма и сопровождаемости.** Программа реализует **копирование выбранного блока и сводную агрегацию для всех 66 индексов**: разделы 4, 5 и 6 файла `st/Программа_ST_1.st` содержат по 66 ветвей и занимают ≈ 1120 строк из 2025.

### 12.2. Принятое решение: полный охват 66 индексов

Параметры создаются для **всех 66 индексов** (иначе не выполнить требование ТЗ «для каждого блока внутри экземпляра — собственные параметры»). А **копирование выбранного блока** работает по **странице** — диапазону из 10 индексов:

| Параметр | Тип | Диапазон | Описание |
|---|---|---|---|
| `СтраницаБлоков` | INT | 1…7 | Номер **отображаемой** страницы окон 5.4 и 5.7: 1 → индексы 1…10, 2 → 11…20, …, 7 → 61…66. На копирование, команды и агрегацию не влияет |
| `ПервыйИндексСтраницы` | INT | Выч | 1, 11, 21, 31, 41, 51, 61 |
| `ПоследнийИндексСтраницы` | INT | Выч | 10, 20, 30, 40, 50, 60, 66 |

**Как это работает:**
1. Программа сравнивает `ВыбранныйБлок` с каждым из 66 индексов и копирует параметры найденного блока в `ВыбранныйБлок…` (§4 программы). Ветвь выбирается по индексу, диапазоном не ограничена.
2. Команды, поданные с элементов окна 5.5, записываются обратно в параметры именно этого индекса (§5 программы).
3. Метки на плане (окно 5.5) и тренды (5.8, 5.9) показывают выбранный блок.
4. Сводная агрегация по всем блокам (§6 программы) считается по 66 индексам независимо от того, какой блок выбран.

**Роль параметра `СтраницаБлоков`.** Он остаётся, но влияет **только на отображение**: окна 5.4 и 5.7 показывают не 66 строк сразу, а страницу из 10. На копирование, команды и агрегацию страница не влияет — это исключает ситуацию «команда ушла не тому блоку, потому что он на другой странице».

> **Это то же самое решение, что в §6.2 «запасной вариант B»** из `паспорт.md`, но применённое не к параметрам, а к **программной части**. Параметры остаются полными для 66 блоков — требование ТЗ выполнено.

### 12.3. Объём программы

**Доработок по охвату индексов не требуется.** Разделы 4, 5 и 6 программы охватывают все 66 индексов; сверка подтверждает, что каждая из 1 830 ссылок на параметры объявлена в этой таблице (702 из них — в индексных разделах), а конструкции `IF/ELSIF/END_IF` сбалансированы во всех 8 программах комплекта.

**Приёмка:** тесты T5-08, T5-09, T5-12 выполняются на индексах 1, 11 и 66 — то есть на границах страниц; это подтверждает, что охват не ограничен первой страницей.

> **Честное замечание.** Программа компилируется и работает на всех 66 индексах. Остаётся **непроверенным в среде** только одно: принимает ли версия 1.3.10.34633 тип с ≈ 903 параметрами (см. §14). Это ограничение среды, а не кода.
