# 12. Каркас общих окон и панелей

Документ задаёт **общую часть** оформления, повторяемую во всех ПБЭ. Состав полей конкретного ПБЭ берётся из его собственной таблицы параметров; здесь — каркас, номера окон и правила наполнения.

Основание: ТЗ приложение 2, рисунки 1.1–1.8 Примера ПБЭ.

### 1.1. Правило согласованности «Шапка ↔ Строка»
В образце «Шапка состояния» — 8 объектов, «Строка состояния» — 25. То есть **строка содержит не одно поле, а блок**. Это значит: у пары «Шапка/Строка» число **колонок** должно совпадать, и для каждой подписи в шапке в строке есть ровно одно поле значения.

**Обязательная проверка при сборке:** перечислить подписи шапки по порядку и убедиться, что поля строки идут в том же порядке и в том же числе. Если разошлись — таблица «поедет».

### 2.4. Панель «Аварии» (четвёртая)
Из рис. 1.1 читается состав (20 строк), состояние — «Норма» / «—» (нет данных):

`Пожар`, `Перепад на приточном вентиляторе`, `Перепад на вытяжном вентиляторе`, `Приточный вентилятор`, `Вытяжной вентилятор`, `Термостат 1`, `Термостат 2`, `Низкая температура воды`, `Низкая температура притока`, `Заслонка притока не открылась`, `Заслонка вытяжки не открылась`, `Ошибка положения заслонки притока`, `Ошибка положения заслонки вытяжки`, `Датчик температуры наружного воздуха`, `Датчик температуры воды`, `Датчик температуры притока`, `Прогрев установки зимой`, `Приточный вентилятор 2`, …

Правила:
* строка аварии = текст + индикатор состояния; индикатор — булев конвертер с `False` первой строкой;
* для аварий, пришедших из маски, текст формирует программа (см. `21_ПБЭ_01/ST`), состояние — по разобранному биту;
* для аварий, пришедших отдельными BOOL, — прямо по признаку, **без разбора маски**;
* `Авария` в шапке панели — общий индикатор (`ЕстьАвария`).

## 3. Окно «Строка» — состав полей по образцу

«Строка» — вертикальный блок для сводной таблицы (рис. 1.2, ~25 полей). Состав полей задаётся описанием параметров конкретного ПБЭ (ТЗ прил. 2), каркас одинаков:

| № поля | Содержимое | Тип отображения | Формат |
|---|---|---|---|
| 1 | Обозначение установки | текст | — |
| 2 | Название | текст | — |
| 3 | Состояние | конвертер состояния | — |
| 4 | Текущий режим | текст | — |
| 5 | Авария | конвертер булев | `Норма`/`Авария` |
| 6 | Температура притока | число | `{f1} °C` |
| 7 | Задание температуры притока | число | `{f1} °C` |
| 8 | Температура вытяжки | число | `{f1} °C` |
| 9 | Температура помещения | число | `{f1} °C` |
| 10 | Температура наружного воздуха | число | `{f1} °C` |
| 11 | Задание скорости притока | число | `{f1} %` |
| 12 | Факт скорости притока | число | `{f1} %` |
| 13 | Задание скорости вытяжки | число | `{f1} %` |
| 14 | Факт скорости вытяжки | число | `{f1} %` |
| 15 | Заслонка притока | конвертер | `Открыта`/`Закрыта` |
| 16 | Заслонка вытяжки | конвертер | `Открыта`/`Закрыта` |
| 17–24 | Поля узлов конкретного ПБЭ (ККБ, рекуператор, насос, фильтр, клапаны) | по таблице параметров | — |
| 25 | Нет связи | конвертер булев | `Есть связь`/`Нет данных` |

**Правило:** поле с форматом `{f1} %` (как в рис. 1.2) — эталон записи формата.

## 4. Пары «Шапка / Строка» для таблиц

### 4.1. Таблица состояния
* **Шапка состояния** (8 объектов) — подписи колонок. Минимальный набор: `Обозначение`, `Название`, `Состояние`, `Режим`, `Задание T`, `Задание V`, `Авария`, `Связь`.
* **Строка состояния** (25 объектов) — те же 8 колонок, значения.

### 4.2. Таблица аварий
* **Шапка аварий** (8 объектов): `Время`, `Обозначение`, `Название`, `Авария`, `Приоритет`, `Активность`, `Квитировано`, `Комментарий`. Источник состава — поля сообщения из рис. А.6 (`Время активации`, `Сообщение`, `Приоритет`, `Активность`, `Время деактивации`, `Квитированность`, `Время квитирования`, `Комментарий`).
* **Строка аварий** (2 объекта) — текст + индикатор; минимальная вставка.

> Шапка и строка — **разные окна** в ПБЭ (разные позиции Перечня), но обязаны быть согласованы по числу и порядку колонок.

## 5. Окно «Точки установок на плане»

Одна позиция Перечня на ПБЭ (кроме № 4, где 4.2 — тоже точки, но для группы).

### 5.1. Одиночная установка (№ 1, 2, 3, 6, 7, 8)
Метка из 1 графического объекта (в образце). Состав метки:
* обозначение установки (`Обозначение`) — **видно при потере связи**;
* индикатор состояния — булев/дискретный конвертер, заливка цветом;
* при необходимости — температура.

Метка кликабельна: событие `MarkerClickEvent` → действие `Action.OpenDialog` на окно «Мнемосхема установки».

### 5.2. Группа из пяти установок (№ 4)
Пять отдельных меток в одном окне 4.2. У каждой — своё обозначение (`В1.1`, `В2.1`, `В3.1`, `В7`, `В9`), своя индикация состояния и своя температура. **Независимость обязательна:** изменение сигнала одной установки не влияет на остальные (тест T7/T8 этапа 1).

### 5.3. Метка блока VRF (№ 5, окно 5.5)
Из ТЗ прил. 2 п. 2.2: **3 графических объекта** — имя блока, **индикатор включения заливкой**, температура.

## 7. Чек-лист оформления (для каждого окна)

| № | Проверка |
|---|---|
| O-1 | Наименование окна — дословно по Перечню ПБЭ |
| O-2 | Число колонок шапки = числу полей строки |
| O-3 | Все цвета конвертеров — `rgb(...)`; цвета текста — `#RRGGBB` |
| O-4 | В каждом булевом конвертере первая строка — `False` |
| O-5 | У каждого поля ввода заполнены «Входящие связи» **и** «Исходящие связи» |
| O-6 | У каждого поля ввода заданы `Минимум`, `Максимум`, `Шаг инкремента` |
| O-7 | Кнопки перехода выполнены действием `Открыть окно` |
| O-8 | Кнопки команд выполнены действием `Задать параметр` |
| O-9 | Кнопка «РАСПИСАНИЕ» присутствует **только** у № 1, 6, 7, 8 |
| O-10 | Группы неиспользуемых узлов скрыты входящей связью на «Видимость» |
| O-11 | Обозначение установки выводится независимо от связи |
| O-12 | Таблица «Обслуживаемые помещения» заполнена и видна при потере связи |
| O-13 | У ПБЭ № 4 нет кнопок, полей уставок, трендов и архивных настроек |
| O-14 | Наименования объектов — по схеме `<Окно>_<Группа>_<Поле>` (или `<№> <День> <№> <Что>` для планировщика) |
