# 10. Общие соглашения по всем 8 ПБЭ

Документ обязателен к соблюдению при разработке **каждого** ПБЭ. Всё, что здесь написано, выведено из Примера ПБЭ и ТЗ; ссылки на рисунки и пункты ТЗ даны в тексте.

---

## 1. Каркас пользовательского библиотечного элемента

Структура повторяет рис. А.1 (элемент `АОВ`):

```
<ИмяПБЭ>                        ← пользовательский библиотечный элемент
├── ➡️ Параметры                    ← параметры типа, верхний уровень
│   ├── Название        STRING   ← обозначение установки
│   ├── Обозначение     STRING   ← код установки (П-1, В1.1, ШУ-В5 …)
│   ├── <вариант>       …        ← параметры выбора исполнения
│   ├── <команды>       BOOL
│   ├── <аварии>        BOOL / DINT
│   └── <измерения>     REAL / INT
└── Ресурсы
    ├── Программы
    │   └── Программа_ST_1        ← ST-программа обработки (может быть не одна)
    ├── Сообщения
    │   └── <Имя сообщения>       ← ресурс сообщения, тип значения BOOL
    └── Окна
        ├── <Окно 1>              ← по Перечню ПБЭ, номера и наименования дословно
        ├── <Окно 2>
        └── …
```

**Правила:**
1. Имена окон — **дословно** как в Перечне ПБЭ, включая скобки: «Настройки (уставки)». Никаких сокращений.
2. Окна разрабатываются **внутри** ПБЭ. Открытие окна или размещение его представления на экране **не создаёт** нового экземпляра ПБЭ (ТЗ п. 1.2).
3. Один тип ПБЭ — на все предусмотренные варианты применения. Различие вариантов — **настройками экземпляра**, не отдельными типами (ТЗ п. 1.1, 1.3).
4. Элемент работает со своими параметрами, **без подключения к конкретному контроллеру** (ТЗ п. 3). Графика показывает, например, параметр элемента «Температура»; к тегу нужной установки его подключает ДИГАМ.

## 2. Именование параметров

### 2.1. Схема префиксов

Схема выведена из имён параметров образца (рис. А.1: `Название`, `Обозначение`, `Включена`, `Отключена`, `СостояниеУст`, `ЗапускУспешен`, `Прогрев`, `ПрогревПрошло`, `ЛетнийРежим`, `Блокировка`, `ОбщаяАвария`, `Авария`) и из имён, читаемых на рисунках 1.1 и А.2 (`АварияКрит1`, `ВариантАварий`, `Пожар`, `АвЗаслВыт`, `АвЗаслПрит`, `АвПолохЗаслРецВыт`, `АвПолохЗаслРецПрит`, `ОбрывТПомещения`, `ЕстьАвария`, `ЕстьПредупр`, `КодАварии`, `КодПредупр`, `Предупреждение`).

| Префикс | Назначение | Тип | Примеры |
|---|---|---|---|
| `Название` | полное обозначение установки/группы | STRING | `Название` |
| `Обозначение` | краткий код | STRING | `Обозначение` = `П-1` |
| `Корпус` | номер корпуса | INT | `Корпус` = 3 |
| `Помещение` … | обслуживаемые помещения | STRING | `Помещение1`, `Помещение1Назначение` |
| `Вкл…` / `Откл…` | команды пуска и останова | BOOL | `Включена`, `Отключена` |
| `Пуск…` / `Стоп…` | команды по узлам | BOOL | `ПускПриток`, `СтопВытяж` |
| `Сброс…` | команды сброса | BOOL | `СбросАварии`, `СбросЗуммера` |
| `Ав…` | авария-признак (BOOL) | BOOL | `АвЗаслВыт`, `АвЗаслПрит`, `АвПолохЗаслРецВыт`, `АвПолохЗаслРецПрит` |
| `Авария…` | аварийное слово/группа | DINT, BOOL | `АварияКрит1`, `АварияПредуп1`, `ОбщаяАвария`, `Авария` |
| `Предупреждение` | признак предупреждения | BOOL | `Предупреждение` |
| `Есть…` | итоговые признаки | BOOL | `ЕстьАвария`, `ЕстьПредупр` |
| `Код…` | код первой аварии/предупреждения | INT, `-1` если нет | `КодАварии`, `КодПредупр` |
| `Т…` | температура | REAL | `ТПритока`, `ТВытяжки`, `ТНарВозд`, `ТОбратнойВоды`, `ТПомещения` |
| `Вл…` | влажность | REAL | `ВлПритока`, `ВлПомещения` |
| `Уст…` | уставка (текущее значение уставки) | REAL, INT | `УстТПритока`, `УстVПритока` |
| `Зад…` | задание (то, что задаёт оператор/планировщик) | REAL, INT, BOOL | `ЗадТПритока`, `ЗадVПритока`, `ЗаданиеСезона` |
| `Настр…` | настройка экземпляра | любой | `НастрЕстьККБ`, `НастрЕстьВлажность` |
| `Выб…` | выбор (перечисление) | INT/STRING | `ВыборОсновногоПритВент`, `ВыборРежима` |
| `Вр…` | время, задержка | TIME | `ВрХодаЗаслонкиПриток` |
| `Мч…` | моточасы | INT (часы) | `МчВент1`, `МчВент2` |
| `Кол…` | счётчик | DINT/INT | `КолПереключенийВент1` |
| `План…` | планировщик | INT, BOOL | `ПланАктивно`, `ПланПнНачалоЧ` |
| `Состояние…` | состояние | STRING/INT | `СостояниеУст`, `СостояниеСистемы` |
| `Запуск…` / `Прогрев…` | этапы работы | BOOL | `ЗапускУспешен`, `Прогрев`, `ПрогревПрошло` |
| `Рез…` | резерв/АВР | BOOL | `РезервАктивен`, `АВРСработал` |
| `Диаг…` | диагностика связи | BOOL | `ДиагНетСвязи` |

### 2.2. Запрещено
* Автоматические имена `Параметр1`, `Var1`, `Текст17`, `Элемент1` — в ПБЭ их быть не должно (в окнах они допустимы как служебные, но лучше именовать).
* Транслит и латиница в именах параметров (кроме служебных полей, которые среда создаёт сама).
* Сокращения, которых нет в таблице §2.1, без записи в этот документ.

### 2.3. Правило различимости вариантов
Если одна и та же сущность есть у притока и у вытяжки — суффиксы **Прит** / **Выт** обязательны: `ПускПрит`, `ПускВыт`, `АвЗаслПрит`, `АвЗаслВыт`. Именно так в образце (`АвЗаслВыт`, `АвЗаслПрит`).

## 3. Именование графических объектов

Из рис. А.5: имя объекта — `3 Пятница 2 Начало час`, то есть
**`<№ интервала> <День недели> <№ поля> <Что>`**.

### 3.1. Планировщик (ПБЭ № 1, 6, 7, 8)
```
1 Понедельник 1 Активация
1 Понедельник 1 Режим работы
1 Понедельник 1 Начало час
1 Понедельник 1 Начало мин
1 Понедельник 1 Конец час
1 Понедельник 1 Конец мин
1 Понедельник 1 Уставка Т
1 Понедельник 1 Уставка V
2 Понедельник 1 Активация
…                       (второй интервал)
```
Дни: `Понедельник, Вторник, Среда, Четверг, Пятница, Суббота, Воскресенье`.

### 3.2. Остальные окна
**`<Окно>_<Группа>_<Поле>`**, например:
```
Мнемосхема_Состояние_СостояниеСистемы
Мнемосхема_Уставки_ЗадТПритока
Мнемосхема_Аварии_Пожар
Настройки_ВодянойНагреватель_УстЗима
Строка_Обозначение
```

### 3.3. Обязательное правило
У любого элемента, который **записывает** значение, заполнены **и** «Входящие связи», **и** «Исходящие связи» (рис. А.4, А.5; ТЗ п. 3: «если элемент управления записывает значение параметра, он должен также читать его текущее значение»).

## 4. Связи графики с параметрами

### 4.1. Форма записи связи
Полное имя параметра (рис. А.3–А.6):
```
Библиотеки.Локальная.Объекты.<ИмяПБЭ>.<ИмяПараметра>
```
При работе внутри экземпляра среда подставляет нужный экземпляр автоматически. В таблицах артефактов связи записываются сокращённо: `<ИмяПБЭ>.<ИмяПараметра>`.

### 4.2. Что на что связывается

| Что | Свойство графики | Куда |
|---|---|---|
| Поле вывода (текст/число) | «Текст» / «Значение» | входящая связь на параметр |
| Поле ввода («Текущее значение») | «Значение» | входящая **и** исходящая связь на параметр |
| Селектор/список | «Выбор» | входящая и исходящая связь на параметр-перечисление |
| Кнопка | событие (см. §6) | действие, а не свойство |
| Группа графики (вариант оборудования) | **«Видимость»** | входящая связь на BOOL-параметр настройки (рис. А.3) |
| Индикатор (заливка, цвет) | конвертер значения | см. `11_Типы_параметров.md` §5 |
| Тренд | «Сигналы»/«Перья» | входящая связь на параметр |

### 4.3. Карта связей как артефакт
Для каждого ПБЭ карта связей оформляется таблицей из 5 колонок:
`Окно | Графический объект | Свойство | Направление связи | Параметр ПБЭ`.
Одна строка = одна связь. Ничего «неявного» — если связи нет в таблице, её нет в проекте.

## 5. Конвертеры значений

### 5.1. Жёсткие требования ТЗ п. 3
| № | Требование | Как выполняется |
|---|---|---|
| K-1 | Цвета в конвертерах — **`rgb(...)`** | формат `rgb(0,128,0)`; **не** `#008000` |
| K-2 | Строка `False` в булевом конвертере — **первая** | порядок строк: `False` → значение/цвет/текст; `True` → значение/цвет/текст |
| K-3 | Цвет **текста** в свойствах графики — `#RRGGBB` (так в рис. А.4: `#202020`) | не путать с K-1 |
| K-4 | Если элемент записывает — он же читает | см. §3.3 |
| K-5 | Команды кнопок — через действия по событию | см. §6 |
| K-6 | Маски аварий, где в образце DINT, сохраняются как **DINT** | `АварияКрит1`, `АварияПредуп1` — DINT |
| K-7 | Если аварии приходят отдельными BOOL — разбор маски **не делается** | для µAria (№ 1 корпус 8, № 6, № 7), Schneider M172 (№ 2) и Zentec (№ 8) |

### 5.1.1. Требования, проверенные в среде (ответы пользователя)

| № | Что проверено | Результат | Влияние на код |
|---|---|---|---|
| K-8 | **Форма строковых литералов в ST** | **двойные кавычки** — `"Стоп"` | Во **всех 8 программах** все 338 литералов записаны в двойных кавычках |
| K-9 | **Имена аргументов функции `LIMIT`** | **`MN`, `IN`, `MX`** | Правки не требуются: во всех 39 вызовах использованы эти имена |
| K-10 | **Функция получения текущего времени** | **`GET_LOCAL_TIME` ОТСУТСТВУЕТ** | **Планировщик переработан**: день недели и время суток принимаются **входными параметрами** (`СистемаДеньНеделиТекст`, `СистемаЧас`, `СистемаМин`). Функции `DT_TO_STRING`, `MID`, `STRING_TO_INT` из программ удалены |
| K-11 | **Функция `TIME → INT`** | **`TIME_TO_INT`** — верное имя | Правки не требуются |
| K-12 | **Запись `TIME := 0`** | **допустима** | Правки не требуются |

> **Практическое следствие K-10.** Планировщик ПБЭ № 1, 6, 7, 8 **не вычисляет** день недели и время самостоятельно, а **принимает их из канала**. ДИГАМ подключает эти три параметра к системному тегу времени в рабочем проекте. Это согласуется с ТЗ п. 3: элемент работает со своими параметрами, а к тегам их подключает ДИГАМ.

### 5.2. Типовая таблица булевого конвертера «авария»
Строки **строго в этом порядке**:

| № строки | Значение | Цвет заливки | Цвет текста | Текст |
|---|---|---|---|---|
| 1 | `False` | `rgb(240,240,240)` | `#202020` | Норма |
| 2 | `True` | `rgb(255,0,0)` | `#FFFFFF` | Авария |

Для предупреждения: строка 2 — `rgb(255,192,0)` / `#202020` / Предупреждение.
Для состояния «работа»: строка 2 — `rgb(0,176,80)` / `#FFFFFF` / Работа.
Для «нет связи»: строка 2 — `rgb(128,128,128)` / `#FFFFFF` / Нет данных.

> Порядок «False первый» — это **требование ТЗ**, а не стилистика. Признак того, что порядок соблюдён: первая строка таблицы конвертера всегда `False`.

### 5.3. Таблица аналогового конвертера (пример «Температура притока»)

| № | Условие | Цвет | Текст |
|---|---|---|---|
| 1 | `< УстТПритока - 5` | `rgb(0,112,192)` | Переохлаждение |
| 2 | `УстТПритока - 5 … УстТПритока + 5` | `rgb(0,176,80)` | Норма |
| 3 | `> УстТПритока + 5` | `rgb(255,0,0)` | Перегрев |

### 5.4. Конвертер дискретного состояния
Значения: `0` → `rgb(240,240,240)` «Стоп»; `1` → `rgb(0,176,80)` «Работа»; `2` → `rgb(255,192,0)` «Предупреждение»; `3` → `rgb(255,0,0)` «Авария»; `4` → `rgb(128,128,128)` «Нет связи».
Порядок строк — по возрастанию кода значения, начиная с 0.

## 6. Команды и кнопки

### 6.1. Механизм
Кнопка не пишет в тег. Кнопка выполняет **действие по событию**:

| Кнопка | Событие | Действие | Параметр |
|---|---|---|---|
| СТАРТ | Нажатие (`MouseEvent`) | `Задать параметр` (`MasterSCADA.View.Action.SetParameter`) | `Включена` := `TRUE` |
| СТОП | Нажатие | `Задать параметр` | `Включена` := `FALSE` |
| СБРОС | Нажатие | `Задать параметр` | `СбросАварии` := `TRUE` |
| РАСПИСАНИЕ | Нажатие | `Открыть окно` (`MasterSCADA.View.Action.OpenDialog`) | окно «Планировщик» |
| Настройки / Диаграммы / Температуры и т. п. | Нажатие | `Открыть окно` | соответствующее окно |

### 6.2. Состав кнопок по ПБЭ (контроль по ТЗ п. 3.1 и прил. 1)

| ПБЭ | СТАРТ | СТОП | СБРОС | РАСПИСАНИЕ | Прочие |
|---|---|---|---|---|---|
| № 1 | да | да | да | **да** | Настройки, тренды |
| № 2 | да | да | да | **нет** | Настройки, тренды |
| № 3 | да | да | да | **нет** | Настройки, тренды |
| № 4 | **нет** | **нет** | **нет** | **нет** | **нет** (только мониторинг) |
| № 5 | да (по выбранному блоку) | да | — | нет | Настройки |
| № 6 | да | да | да | **да** | Настройки, тренды |
| № 7 | да | да | да | **да** | Настройки, тренды |
| № 8 | да | да | да + **СБРОС ЗУММЕРА** | **да** | Настройки, тренды |

### 6.3. Отключённые функции
Неиспользуемые функции гасятся настройками экземпляра: соответствующая графика скрыта, а программа **не формирует** команду по отключённой функции (ТЗ п. 1.3, 3.2). Кнопка отключённой функции в окне не отображается.

## 7. Сообщения

Из рис. А.6:
1. Сообщение — ресурс элемента: `Ресурсы → Сообщения → <Имя>`.
2. Имя сообщения = имя BOOL-параметра-признака (`Пожар`, `Перепад приток`, `Термостат 1`, `Нет прогрева` …).
3. Внутренние элементы сообщения: `Время активации`, `Сообщение`, `Приоритет`, `Активность`, `Время деактивации`, `Квитированность`, `Время квитирования`, `Комментарий`, `Время изменения`.
4. `Тип значения` = **BOOL**; `Отношения` = «Прием значения из».
5. Активность сообщения — **входящей связью** на одноимённый параметр элемента.
6. Архивирование сообщения — флажок `Архивировать` + `Шаблон архивирования`.

**Правило:** сообщение создаётся **на каждый** BOOL-параметр, помеченный в таблице параметров ПБЭ как «аварийный признак». Список сообщений ПБЭ = список таких параметров.

## 8. Тренды и архивирование

### 8.1. Тренды
Окна-тренды (по Перечню): «Температуры», «Общая диаграмма», «Производительность вентиляторов», «Дискретные значения» — у № 1, 2, 3, 6, 7, 8; «Температуры» и «Дискретные значения» — у № 5. У ПБЭ № 4 трендов **нет**.

Сигналы трендов задаются по образцу (легенды рис. 1.6–1.8):
* «Температуры» — аналоговые температуры (приток, вытяжка, наружный воздух, обратная вода, помещение: только применимые);
* «Общая диаграмма» — сводный набор температур и влажностей;
* «Производительность вентиляторов» — задание и факт по притоку и вытяжке;
* «Дискретные значения» — ступенчатый график дискретных сигналов (пуск, заслонки, вентиляторы, аварии).

### 8.2. Архивирование
* Настраивается **на параметрах типа** (ТЗ п. 3: «Если предусмотрено архивирование, оно настраивается на параметрах типа»).
* «Образец ПБЭ» (рис. А.1) помечает флажком архивирования контрольные параметры: `Состояние`, `Прогрев`, `ЛетнийРежим` — вместе с трендом; остальные — только архивирование.
* Сообщения архивируются флажком `Архивировать` (рис. А.6).
* Конкретный `Шаблон архивирования` берётся из библиотеки стандартных шаблонов (`MasterSCADA.Library.StandardArchiveTemplates`).

## 9. Обязательные сквозные параметры (в каждом ПБЭ, кроме № 4 в части команд)

| Параметр | Тип | Назначение |
|---|---|---|
| `Название` | STRING | обозначение установки; **видно при потере связи** (ТЗ п. 3) |
| `Обозначение` | STRING | код установки; **видно при потере связи** |
| `Корпус` | INT | номер корпуса |
