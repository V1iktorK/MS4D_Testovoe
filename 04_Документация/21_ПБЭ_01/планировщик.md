# ПБЭ № 1. Планировщик работы установки

**Окно:** 1.4 «Планировщик». **Панель:** «Планировщик» в окне 1.1.
**Применяется также в:** ПБЭ № 6, № 7, № 8 (ТЗ п. 3.2: «Для всех вариантов оборудования применяется одинаковый принцип работы»).
**Не применяется в:** ПБЭ № 2, № 3 (ТЗ п. 3.1 и прил. 1 ч. 2).

---

## 1. Требования ТЗ (дословно)

> «ПБЭ № 1, 6, 7 и 8 содержат универсальный планировщик, выполняющий расписание средствами MasterSCADA 4D. Для всех вариантов оборудования применяется одинаковый принцип работы.
> Исполнитель реализует **полный функционал планировщика по образцу: недельное расписание, интервалы работы, включение и отключение установки, выбор режима, задание температуры и скорости вентилятора**.
> Расписание и применимые функции настраиваются отдельно для каждого экземпляра ПБЭ в соответствии с возможностями конкретной установки. **Неиспользуемые функции отключаются настройками экземпляра, соответствующие поля скрываются, команды по отключённым функциям не формируются.**
> **SCADA формирует команды через параметры экземпляра ПБЭ. Запись расписания во встроенные программы контроллеров не предусматривается.**»

**Разложение на пять обязательных элементов:**

| № | Требование | Где реализовано |
|---|---|---|
| 1 | **недельное расписание** | 7 дней × 2 интервала, §3 |
| 2 | **интервалы работы** | `НачалоЧ/Мин`, `КонецЧ/Мин` + `Активация`, §3–§4 |
| 3 | **включение и отключение установки** | `ПланВключить` / `ПланОтключить` → `Включена`, §5 |
| 4 | **выбор режима** | `РежимРаботы` интервала → `ЗадРежима`, §5 |
| 5 | **задание температуры и скорости вентилятора** | `УставкаT` → `ЗадТПритока`, `УставкаV` → `ЗадVПритока`, §5 |
| + | неиспользуемые функции отключаются настройками, команды не формируются | `ПланРасписаниеАктивно`, `Активация`, флаг `НастрЕстьСкорость` — §6 |
| + | команды формируются **только через параметры экземпляра**, записи в контроллер нет | §5, §7 |

## 2. Что взято из образца

### 2.1. Полная форма — рисунок 1.4 «Окно "Планировщик"»

Заголовок окна: **«Планировщик работы установки»**. Верхняя строка:
* `Расписание активно` — переключатель;
* `Режим расписания` — селектор («выбор» в образце).

Далее — **7 колонок** по дням недели: `Понедельник`, `Вторник`, `Среда`, `Четверг`, `Пятница`, `Суббота`, `Воскресенье`.

В каждой колонке — **два интервала** с заголовками `Интервал 1` и `Интервал 2`.

Состав полей интервала (дословно с рис. 1.4):

| Поле на рисунке | Тип элемента | Значение в образце |
|---|---|---|
| `Активация` | селектор («выбор») | пусто |
| `Режим работы` | селектор («выбор») | пусто |
| `Начало` | **два** поля | `50` и `50` |
| `Конец` | **два** поля | `50` и `50` |
| `Уставка Т, °C` | поле ввода | `50` |
| `Уставка V, %` | поле ввода | `50` |

### 2.2. Компактная панель — рисунок 1.1, панель «Планировщик»

Две таблицы: **«Интервал 1»** и **«Интервал 2»**. Колонки: `День` / `Время` / `Скорость`.
Строки: `Пн … Вс` (на рисунке аббревиатуры не читаются, но это семь дней недели).
В колонке `Время` — **два поля** (`50` и `53` на рис. 1.1), то есть часы и минуты.

**Вывод:** панель в мнемосхеме — **представление тех же параметров**, что и полная форма. Отдельных параметров для панели не создаётся.

### 2.3. Именование графических объектов — рисунок А.5

Образец даёт имя объекта: **`3 Пятница 2 Начало час`**.
Разбор этого имени: `<№ интервала> <День недели> <№> <Что>`.

Отсюда принятая схема имён объектов окна 1.4:

```
1 Понедельник 1 Активация
1 Понедельник 1 Режим работы
1 Понедельник 1 Начало час
1 Понедельник 1 Начало мин
1 Понедельник 1 Конец час
1 Понедельник 1 Конец мин
1 Понедельник 1 Уставка Т
1 Понедельник 1 Уставка V
2 Понедельник 1 Активация
… (второй интервал)
```
и так для всех семи дней: **7 × 2 × 8 = 112 графических объектов** в окне 1.4.

### 2.4. Свойства полей ввода — рисунок А.5

| Свойство | Значение в образце | Что задаём мы |
|---|---|---|
| `Шаг инкремента` | `1` | `1` |
| `Минимум` | `0` | по диапазону параметра |
| `Максимум` | `100` | по диапазону параметра (**часы — 23, минуты — 59**) |
| `Текущее значение` | `50` | значение параметра |
| `Входящие связи` | одна | **заполнено** |
| `Исходящие связи` | одна | **заполнено** |
| `Использовать вход…` | вкл | вкл |
| `Масштаб кол-во знаков` | `0` | `0` |
| `Мгновенное получ…` | выкл | выкл |

> **Внимание.** **В образце `Максимум = 100`.** Это значение для интервала 0…100. Для **часов** ставим `Максимум = 23`, для **минут** — `59`. Иначе оператор сможет ввести «25:70». Обоснование: образец показывает значения полей для одного произвольного элемента; диапазон задаётся по смыслу параметра. См. допущение `D-06`.

## 3. Структура параметров

### 3.1. Схема имён

```
План<День><Интервал><Поле>
```

| Часть | Значения |
|---|---|
| `<День>` | `Пн`, `Вт`, `Ср`, `Чт`, `Пт`, `Сб`, `Вс` |
| `<Интервал>` | `1`, `2` |
| `<Поле>` | `Активация`, `РежимРаботы`, `НачалоЧ`, `НачалоМин`, `КонецЧ`, `КонецМин`, `УставкаT`, `УставкаV` |

**Примеры:**
`ПланПн1Активация`, `ПланПн1РежимРаботы`, `ПланПн1НачалоЧ`, `ПланПн1НачалоМин`, `ПланПн1КонецЧ`, `ПланПн1КонецМин`, `ПланПн1УставкаT`, `ПланПн1УставкаV`,
`ПланПт2Активация`, …, `ПланВс2УставкаV`.

### 3.2. Типы и диапазоны

| Поле | Тип | Мин | Макс | По умолч. | Примечание |
|---|---|---|---|---|---|
| `Активация` | BOOL | — | — | FALSE | Интервал активен |
| `РежимРаботы` | INT | 0 | 2 | 0 | 0 Авто, 1 Ручной, 2 Стоп |
| `НачалоЧ` | INT | 0 | 23 | 8 | Часы начала |
| `НачалоМин` | INT | 0 | 59 | 0 | Минуты начала |
| `КонецЧ` | INT | 0 | 23 | 17 | Часы окончания |
| `КонецМин` | INT | 0 | 59 | 0 | Минуты окончания |
| `УставкаT` | REAL | 5 | 40 | 20 | Уставка температуры, °C |
| `УставкаV` | INT | 0 | 100 | 50 | Уставка скорости, % |

### 3.3. Общие параметры

| Параметр | Тип | По умолч. | Описание |
|---|---|---|---|
| `ПланРасписаниеАктивно` | BOOL | FALSE | Общий выключатель расписания |
| `ПланРежимРасписания` | INT | 0 | 0 Рабочий день, 1 Выходной, 2 Праздник, 3 Дежурный |

### 3.4. Источник текущего времени (3 параметра) — **уточнение по среде**

> **Внимание.** **Важно.** Штатной функции получения текущего времени в MasterSCADA 4D 1.3.10.34633 **НЕТ** — функция `GET_LOCAL_TIME` в среде **отсутствует** (проверено пользователем).

Поэтому день недели и время суток планировщик **не вычисляет**, а **принимает параметрами**:

| Параметр | Тип | Напр. | Диапазон | Описание |
|---|---|---|---|---|
| `СистемаДеньНеделиТекст` | STRING | **Вх** | `Пн` … `Вс` | Текущий день недели |
| `СистемаЧас` | INT | **Вх** | 0…23 | Текущий час |
| `СистемаМин` | INT | **Вх** | 0…59 | Текущие минуты |

**Как это работает:**
1. ДИГАМ подключает эти три параметра к **системному тегу времени** в рабочем проекте.
2. Программа ограничивает принятые значения (`Час` → 0…23, `Мин` → 0…59), чтобы неверный сигнал не сломал расписание.
3. Далее логика планировщика работает как описано в §4 — сравнение `ТекСек` с границами интервалов.

**Почему так, а не иначе.** ТЗ п. 3: «Элемент работает со своими параметрами, без подключения к конкретному контроллеру. Например, графика показывает параметр элемента «Температура»; к тегу нужной установки его подключает ДИГАМ». Тот же принцип применён ко времени: **ПБЭ принимает его как внешнюю величину**.

**Что нужно проверить при сборке:** есть ли в MasterSCADA 4D системный тег времени, пригодный для подключения. Если такого тега нет — сообщите мне: день недели придётся формировать иначе (например, отдельной программой в проекте ДИГАМ).

### 3.5. Выходы планировщика (только чтение для оператора)

| Параметр | Тип | Описание |
|---|---|---|
| `ПланВключить` | BOOL | Команда «включить» |
| `ПланОтключить` | BOOL | Команда «отключить» |
| `ПланЗадT` | REAL | Задание температуры |
| `ПланЗадV` | INT | Задание скорости |
| `ПланЗадРежим` | INT | Задание режима |
| `ТекущийИнтервал` | INT | -1 нет активного, 1 или 2 |
| `КомандаПоРасписанию` | BOOL | Команда пришла от планировщика, а не от оператора |

**Итого параметров планировщика:** 7 × 2 × 8 = **112** + 2 общих + **3 источника времени** + 7 выходов = **124**.

## 4. Алгоритм: определение активного интервала

### 4.1. Идея

Для текущего дня недели и текущего времени суток проверяются оба интервала. Активным считается тот, чей признак `Активация = TRUE` и текущее время попадает в границы `[Начало, Конец)`.

**Полуинтервал `[Начало, Конец)`** — начало включается, конец нет. Это исключает двойное срабатывание на стыке двух интервалов («10:00–12:00» и «12:00–14:00»): в 12:00 активен только второй.

### 4.2. Границы интервала в секундах от полуночи

```
Граница  = Часы × 3600 + Минуты × 60
```

### 4.3. Условие активности

```
Активен = Активация
          И (ГраницаНачала < ГраницаКонца)
          И (ТекущееВремя >= ГраницаНачала)
          И (ТекущееВремя <  ГраницаКонца)
```

### 4.4. Ночные интервалы (через полночь)

Если `ГраницаНачала >= ГраницаКонца`, интервал считается переходящим через полночь:
```
Активен = Активация
          И (ГраницаНачала > ГраницаКонца)
          И ((ТекущееВремя >= ГраницаНачала) ИЛИ (ТекущееВремя < ГраницаКонца))
```
**Пример:** интервал «22:00 … 06:00» активен с 22:00 до полуночи и с полуночи до 06:00.

> **Это расширение образца.** В образце ночные интервалы не описаны; реализовано, потому что для вентиляции ночной режим типичен, а поведение без этого было бы неопределённым. Помечается как допущение `D-60a`. Если ДИГАМ ночные интервалы не нужны — условие не мешает: при корректных дневных границах оно не срабатывает.

### 4.5. Приоритет при пересечении интервалов

Если активны **оба** интервала (например, «08:00–20:00» и «12:00–13:00»), приоритет — у **второго**. Обоснование: второй интервал в расписании обычно описывает частный случай (обеденный перерыв, технологическое окно). `ТекущийИнтервал` = 2.

### 4.6. Выбор дня недели

Номер дня недели берётся из текущей даты. Соответствие:

| День | Ветка программы |
|---|---|
| Понедельник | `План Пн…` |
| Вторник | `План Вт…` |
| Среда | `План Ср…` |
| Четверг | `План Чт…` |
| Пятница | `План Пт…` |
| Суббота | `План Сб…` |
| Воскресенье | `План Вс…` |

## 5. Формирование команд

### 5.1. Что формируется

| Выход планировщика | Как формируется | Куда идёт |
|---|---|---|
| `ПланВключить` | `TRUE`, если есть активный интервал | → `Включена := TRUE` |
| `ПланОтключить` | `TRUE`, если расписание активно, но активного интервала нет | → `Включена := FALSE` |
| `ПланЗадT` | `УставкаT` активного интервала | → `ЗадТПритока` |
| `ПланЗадV` | `УставкаV` активного интервала | → `ЗадVПритока` |
| `ПланЗадРежим` | `РежимРаботы` активного интервала | → `ЗадРежима` |

### 5.2. Как команда применяется

**Ключевое требование ТЗ:** «SCADA формирует команды **через параметры экземпляра ПБЭ**. Запись расписания во встроенные программы контроллеров не предусматривается.»

Значит:
* планировщик **не пишет** в теги контроллера;
* планировщик пишет в **параметры ПБЭ** (`Включена`, `ЗадТПритока`, `ЗадVПритока`, `ЗадРежима`);
* ДИГАМ подключает эти параметры к тегам установки.

### 5.3. Приоритет ручного управления

Если оператор перевёл установку в режим `Ручной` (`ЗадРежима = 1`), команды планировщика **не применяются** — расписание не должно «перебивать» оператора.

```
ПрименятьРасписание = ПланРасписаниеАктивно
                      И (ЗадРежима <> 1)          (* не ручной *)
                      И НЕ Блокировка
                      И НЕ ДиагНетСвязи
```

### 5.4. Неиспользуемые функции не формируют команд

ТЗ п. 3.2: «Неиспользуемые функции отключаются настройками экземпляра, соответствующие поля скрываются, команды по отключённым функциям не формируются.»

| Функция | Флаг | Что происходит при `FALSE` |
|---|---|---|
| Задание температуры | `НастрПланЗадT` | `УставкаT` игнорируется, `ПланЗадT` не формируется, поля скрыты |
| Задание скорости | `НастрПланЗадV` | `УставкаV` игнорируется, `ПланЗадV` не формируется, поля скрыты |
| Выбор режима | `НастрПланРежим` | `РежимРаботы` игнорируется, `ПланЗадРежим` не формируется, поля скрыты |
| Интервал 2 | `НастрПланИнтервал2` | Второй интервал не обрабатывается, его поля скрыты |
| Расписание целиком | `ПланРасписаниеАктивно` | Команды не формируются, `ТекущийИнтервал = -1` |

> **Практическое следствие:** если у установки нет регулирования температуры (только вентилятор), `НастрПланЗадT = FALSE` — и поля `Уставка T, °C` в окнах 1.4 и панели 1.1 **скрыты**, а `ПланЗадT` остаётся нулевым.

## 7. Что планировщик НЕ делает (прямые запреты ТЗ)

| Не делает | Обоснование |
|---|---|
| **Не записывает расписание во встроенные программы контроллеров** | ТЗ п. 3.2 прямо: «Запись расписания во встроенные программы контроллеров не предусматривается» |

| Не переключает сезон автоматически по календарю | Сезон в ПБЭ № 1 — отдельная функция (`ЗаданиеСезона`, `ТекущийСезон`) |

### 8.2. Состав графических объектов
**112 полей** (7 дней × 2 интервала × 8 полей) + 2 общих + 7 индикаторов состояния + 1 кнопка возврата = **≈ 122 объекта**.

### 8.3. Имена графических объектов
По схеме образца (рис. А.5): `<№ интервала> <День недели> <№> <Что>`.
Примеры: `1 Понедельник 1 Начало час`, `2 Пятница 2 Уставка V`.

### 8.4. Панель «Планировщик» в окне 1.1
Две таблицы по рис. 1.1:
* таблица «Интервал 1» — колонки `День` / `Время` / `Скорость`, 7 строк;
* таблица «Интервал 2» — то же.

Поля — **те же параметры**, что в окне 1.4 (не дублируются). Кнопка `РАСПИСАНИЕ` в панели «Состояние» окна 1.1 открывает окно 1.4 действием `Открыть окно`.

## 9. Программа планировщика

Полный код — в файле `st/Программа_ST_1.st`, раздел 6. Здесь — описание логики.

```
1. Получить текущий день недели и время суток ИЗ ПАРАМЕТРОВ
   (СистемаДеньНеделиТекст, СистемаЧас, СистемаМин) и ограничить значения.
2. Для текущего дня вычислить границы интервала 1 и 2 (в секундах от полуночи).
3. Определить, активен ли интервал 1; затем интервал 2 (приоритет 2).
4. Установить ТекущийИнтервал (-1 / 1 / 2) и КомандаПоРасписанию.
5. Если ТекущийИнтервал = 1  -> применить параметры интервала 1.
   Если ТекущийИнтервал = 2  -> применить параметры интервала 2.
   Если -1                    -> ПланОтключить := TRUE (если расписание активно).
6. Применить настройки применимости (НастрПлан…):
   НастрПланЗадT = FALSE -> ПланЗадT не формируется
   НастрПланЗадV = FALSE -> ПланЗадV не формируется
   НастрПланРежим = FALSE -> ПланЗадРежим не формируется
7. Применить ПланВключить/ПланОтключить/ПланЗад* к параметрам ПБЭ
   (Включена, ЗадТПритока, ЗадVПритока, ЗадРежима) — ТОЛЬКО через параметры
   экземпляра, без записи в теги контроллера.
8. Подавить команды расписания при ручном режиме, блокировке, потере связи.
```

### 9.1. Отсутствие массивов — осознанное решение
Планировщик обрабатывается **явным выбором дня** (`CASE` по дню недели), а не массивами параметров. Причины:
* состав параметров задаётся таблицей, а не структурой;
* исключается зависимость от поддержки массивов параметров в версии 1.3.10;
* код читается построчно против Перечня, что упрощает приёмку.

## 13. Проверки планировщика (выносятся в тесты)

| № | Проверка |
|---|---|
| П-1 | Расписание активно = FALSE ⟹ команды не формируются, `ТекущийИнтервал = -1` |
| П-2 | Текущее время внутри интервала ⟹ `ПланВключить = TRUE`, `Включена` устанавливается |
| П-3 | Текущее время вне интервалов ⟹ `ПланОтключить = TRUE` |
| П-4 | `Активация = FALSE` ⟹ интервал игнорируется |
| П-5 | Границы интервала: начало включается, конец **не** включается |
| П-6 | Стык двух интервалов («10–12» и «12–14») в 12:00 ⟹ активен только второй |
| П-7 | Пересечение интервалов ⟹ приоритет у интервала 2 |
| П-8 | Ночной интервал «22:00–06:00» активен в 23:00 и в 05:00, неактивен в 12:00 |
| П-9 | Смена дня недели ⟹ применяются параметры нового дня |
| П-10 | `НастрПланЗадT = FALSE` ⟹ `ПланЗадT` не формируется, поля `Уставка T` скрыты |
| П-11 | `НастрПланЗадV = FALSE` ⟹ `ПланЗадV` не формируется, поля скрыты |
| П-12 | `НастрПланРежим = FALSE` ⟹ `ПланЗадРежим` не формируется, поля скрыты |
| П-13 | `НастрПланИнтервал2 = FALSE` ⟹ интервал 2 не обрабатывается, поля скрыты |
| П-14 | `ЗадРежима = 1` (Ручной) ⟹ команды расписания не применяются |
| П-15 | `Блокировка = TRUE` ⟹ команды расписания не применяются |
| П-16 | `ДиагНетСвязи = TRUE` ⟹ команды расписания не применяются |
| П-17 | `Уставка T` применяется к `ЗадТПритока`, `Уставка V` — к `ЗадVПритока` |
| П-18 | **В теги контроллера не пишется ничего** — планировщик воздействует только на параметры ПБЭ |
| П-19 | Окно 1.4 содержит **112** полей, у **каждого** обе связи |
| П-20 | Наименования объектов по схеме `<№ интервала> <День> <№> <Что>` (по рис. А.5) |
| П-21 | `Максимум` для часов = 23, для минут = 59 (не 100, как в образце для общих полей) |
| П-22 | Кнопка «РАСПИСАНИЕ» открывает окно 1.4 действием `Открыть окно` |
| П-23 | Панель «Планировщик» в окне 1.1 использует **те же** параметры, что окно 1.4 (не дублирует) |
