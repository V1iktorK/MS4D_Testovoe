## 9. Программа ST

### 9.1. Объём и структура
**803 строки**, 9 разделов.

| Раздел | Содержание |
|---|---|
| 0 | **Выбор варианта оборудования**: для µAria принудительно `НастрЕстьВлажность := FALSE`, `НастрРазборМаски := FALSE`; гашение признаков отключённых узлов |
| 1 | Ограничение вводимых уставок (`LIMIT` + границы целых) |
| **2** | **Разбор битовых масок** — только при `НастрРазборМаски = TRUE`; раскладка дословно по рис. А.2; цикл `FOR i := 0 TO 8` для `n` и `k` |
| **3** | **Отдельные логические признаки** — 3.1 критические всегда, 3.2 критические по составу, **3.3 предупредительные**. Итог: `КолАварий := n + КритОтд`, `ЕстьАвария`, `ЕстьПредупр`, коды `-1` |
| 4 | **Планировщик** — 4.1 время, 4.2 активный интервал по дню недели, 4.3 приоритет интервала 2, 4.4 применение к параметрам ПБЭ |
| 5 | Управление, **АВР**, команды, сезон, нагрев/охлаждение |
| 6 | Состояния узлов текстом |
| 7 | Расход |
| 8 | Состояние установки по приоритету |

### 9.2. Ключевые решения

| Решение | Обоснование |
|---|---|
| **Два независимых пути аварий** | ТЗ требует разбор масок для pCO XS/c.pCO и **запрещает** его для µAria. Оба пути в одной программе, переключаются `НастрРазборМаски` |
| **Биты 5, 6 учитываются в `n`, но не разбираются** | Дословно по рис. А.2: «Аварии вентиляторов приходят и отдельными точками, их пишет канал» |
| **`n` и `k` — как в образце** | Имена переменных сохранены (`n`, `k`), чтобы код читался против рис. А.2 построчно |
| **Разделение критических и предупредительных признаков** | Панель «Аварии» образца (рис. 1.1) содержит обе группы; термостаты и низкие температуры — предупреждения, а не критические аварии |
| **Источник времени — входные параметры** | Функции получения текущего времени в среде **нет** (проверено пользователем). Поэтому день недели и время суток принимаются параметрами `СистемаДеньНеделиТекст`, `СистемаЧас`, `СистемаМин`. Это соответствует ТЗ п. 3: элемент работает со своими параметрами, к системному тегу времени их подключает ДИГАМ |
| **Ночные интервалы** | Если `Начало >= Конец`, интервал считается переходящим через полночь (**допущение `D-60a`**) |
| **Полуинтервал `[Начало, Конец)`** | Исключает двойное срабатывание на стыке интервалов |
| **Приоритет интервала 2** | Второй интервал — частный случай (обед, техокно) |
| **Подавление расписания при ручном режиме** | Оператор главнее расписания: `ЗадРежима <> 1` в условии применения |
| **Команды только через параметры ПБЭ** | Прямое требование ТЗ п. 3.2; записи в теги контроллера нет ни одной строкой |
| **Уставки интервала берутся по текущему дню** | Чтобы не дублировать разбор дня, ветки `IF День = 'Пн'` вынесены в отдельные блоки после определения `ТекущийИнтервал` |

### 9.3. Форма кавычек и имена аргументов
Использованы **двойные** кавычки (`"Пн"`, `"Стоп"`, `"Работа"` и др. — форма подтверждена в среде) и именованные аргументы `LIMIT(MN := …, IN := …, MX := …)` (имена подтверждены).
Если компилятор требует иного — заменить во всём файле и сообщить: правка распространится на все восемь программ комплекта.
