# ПБЭ № 3. Инструкция по сборке в MasterSCADA 4D 1.3.10.34633

**Кто выполняет:** пользователь. Материал — этот документ плюс `параметры.md`, `окна_и_связи.md`, `st/Программа_ST_1.st`.
**Что получится:** заготовка библиотечного элемента с 12 окнами и ~83 параметрами, проверенная на тестовых значениях.
**Оценка времени:** ≈ 14 ч.

> **Ключевая идея.** ПБЭ № 3 — не «недоделанный ПБЭ», а **заготовка по требованию ТЗ**. Окна, параметры, элементы управления и связи создаются полностью и проверяются на тестовых значениях. Логика ШУВ-К (переменные шкафа, приводы, резерв, общие команды, входы Q7…QB) **сознательно не разрабатывается** — это прямая норма ТЗ, приложение 1, часть 2.
>
> **Не пытайтесь «дополнить» ПБЭ № 3 логикой резерва или входами Q7…QB.** Это нарушит ТЗ. Проверяется тестами T3-14…T3-18.

3. Открыть рядом `30_ПБЭ_03/параметры.md` и `30_ПБЭ_03/окна_и_связи.md`.

**Проверка:** проект открывается, ПБЭ № 4 на месте и не повреждён.

## Шаг 4. Программа ST (1 ч)

1. `Ресурсы → Программы` → создать `Программа_ST_1`, язык ST.
2. Скопировать **весь** текст из `st/Программа_ST_1.st`.
3. Скомпилировать.

**Если ошибки:**

| Ошибка | Причина | Что делать |
|---|---|---|
| «Неизвестный идентификатор `НомРасходаВытяжки`» | параметр не создан | сверить с §6.2 |
| Ошибка на строковых литералах | строка повреждена при копировании | вставить файл программы целиком: кавычки двойные, форма подтверждена при проверке среды |
| Ошибка на `LIMIT` | иные имена аргументов в этой сборке | проверить подсказку среды; вероятные варианты `MN/IN/MX` или `MIN/IN/MAX`; сообщить мне |
| Ошибка на `CASE … OF` | не хватает ветки `ELSE` | ветка `ELSE` в файле есть, проверить, что не обрезана при вставке |

**Проверка шага:** программа компилируется. **Тест:** T3-26.

> **Важно.** Программа **не содержит** вызовов `GetBit`, не реализует логику резерва, не назначает входы Q7…QB. Это правильно.

## Шаг 5. Окно 3.1 «Мнемосхема установки» (3 ч)

### 5.1. Создание
`Ресурсы → Окна` → создать окно с именем **строго** `Мнемосхема установки`. Размер ≈ 1400 × 900.

### 5.2. Заголовок
`Текст_Название` ← `Название`; `Текст_Шкаф` ← `Шкаф`; `Текст_Корпус` ← `Корпус`.

### 5.3. Мнемосхема — ВЫТЯЖНАЯ
Разместить узлы по эскизу `окна_и_связи.md` §2.1:

| Узел | Что разместить | Обязательно? |
|---|---|---|
| Фильтр вытяжки + перепад | Гр_Фильтр + индикатор + текст | при `НастрЕстьФильтр` |
| Заслонка притока | Гр_ЗаслонкаПриток + индикатор + текст | при `НастрЕстьЗаслонкаПриток` |
| Заслонка вытяжки | Гр_ЗаслонкаВытяж + индикатор + текст | при `НастрЕстьЗаслонкаВытяж` |
| Вентилятор вытяжки 1 | Гр_Вент1 + рисунок + индикатор + текст V | при `НастрЕстьВент1` |
| Вентилятор вытяжки 2 | Гр_Вент2 + рисунок + индикатор + текст V | при `НастрЕстьВент2` |
| Нагреватель | Гр_Нагреватель + индикатор | при `НастрЕстьНагреватель` |
| Датчики T | T вытяжки, T притока, T помещения, T наружного | T помещения и T наружного — по настройкам |

> **Внимание.** **НЕ размещать:** калорифер (в полном составе), **пароувлажнитель**, **ККБ**, **рекуператор**, **насос**, **вентилятор притока как узел**. Это узлы приточной установки. Проверяется тестом **T3-05**.

### 5.4. Скрытие узлов
Для каждой группы по настройке: выделить группу → свойство **«Видимость»** → входящая связь на `Настр…` (рис. А.3).

### 5.5. Панель «Состояние»
`Текст_СостояниеСистемы` ← `СостояниеСистемы`; `Текст_ТекущийРежим` ← `ТекущийРежим`; `Селектор_ЗадРежима` ← `ЗадРежима` (**обе связи**).

Кнопки (действие `Задать параметр` по событию нажатия):
* `Кнопка_Стоп` → `Включена := FALSE`;
* `Кнопка_Старт` → `Включена := TRUE`;
* `Кнопка_Сброс` → `СбросАварии := TRUE`;
* `Кнопка_ЖурналСообщений` → действие `Открыть окно` (журнал сообщений).

> **Внимание.** **Кнопку `РАСПИСАНИЕ` НЕ создавать.** Ни в этом окне, ни где-либо ещё. Тесты **T3-09**, **T3-12**.

### 5.6. Панель «Уставки»
8 полей ввода (обе связи, `Минимум`/`Максимум`/`Шаг`/`Текущее значение`): `УстТВытяжки`, `УстТПритока`, `ЗадТПритока`, `ЗадVПритока`, `ЗадVВытяжки`, `МинТПритока`, `ТПереходаЛето`, `ТПереходаЗима`.

### 5.7. Панель «Аналоговые значения»
5 строк аналоговых + блок «Состояние компонентов» (4 строки: заслонки и вентиляторы).

### 5.8. Панель «Аварии»
10 строк индикации по списку `окна_и_связи.md` §2.2.

### 5.9. Панель «Диаграммы»
5 кнопок перехода (действие `Открыть окно`): Температуры → 3.4, Общая диаграмма → 3.5, Производительность вентиляторов → 3.6, Дискретные значения → 3.7, Настройки → 3.3.

> **Внимание.** **Кнопки «Планировщик» в панели «Диаграммы» НЕТ.**

### 5.10. Таблица «Обслуживаемые помещения»
3 строки: `ПомещениеK` / `ПомещениеKНазначение`.

**Проверка шага:** T3-05, T3-06, T3-07, T3-08, T3-09, T3-12, T3-13.

## Частые ошибки и что делать

| Симптом | Причина | Решение |
|---|---|---|
| В мнемосхему «затащили» рекуператор или увлажнитель | скопировали узлы из окна 1.1 образца | удалить: это приточные узлы (ТЗ п. 3.1) |
| Появилась кнопка «РАСПИСАНИЕ» | скопировали панель «Состояние» из образца целиком | удалить кнопку (ТЗ п. 3.1) |
| Появилась панель «Планировщик» | скопировали компоновку из рис. 1.1 целиком | удалить панель |
| Таблица состояния «поехала» | поля строки не совпадают с колонками шапки | сверить по `окна_и_связи.md` §6, выровнять |
| Узел виден при `Настр… = FALSE` | связь на «Активность», а не на «Видимость» | свойство **«Видимость»** |
| Норма и авария перепутаны | `True` первой строкой конвертера | поставить `False` первой |
| Цвет не применился | задан `#RRGGBB` в конвертере | заменить на `rgb(...)` |
| Команда `ПускВент2` «залипла» | `НастрЕстьВент2 = FALSE`, но программа не выполняется | проверить, что `Программа_ST_1` привязана к элементу |
| Состояние всегда «Нет данных» | `ДиагНетСвязи` по умолчанию TRUE | задать FALSE |
| Компилятор ругается на `LIMIT` | другие имена аргументов | сообщить мне — поправлю во всех ПБЭ |
| Компилятор ругается на кавычки | среда требует двойные | заменить `'` → `"` и сообщить мне |
| Пытаетесь дописать логику резерва | непонимание статуса заготовки | **НЕ надо.** ТЗ прил. 1 ч. 2 прямо запрещает |
