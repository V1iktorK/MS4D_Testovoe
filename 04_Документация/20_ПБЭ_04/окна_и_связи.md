| 5 | `МеткаN_Связь` | Значение / Заливка | Входящая | `ДиагНетСвязиN` |

### 2.4. Независимость меток — ключевое требование
Каждая метка связана **только** с параметрами своего индекса N. Никаких общих промежуточных параметров между метками нет. Это обеспечивает выполнение требования ТЗ «независимая индикация состояния по дискретным сигналам» и проверяется тестами T-12, T-13.

### 2.5. Кликабельность
Клик по метке — **не предусмотрен**: у ПБЭ № 4 нет окон, на которые можно перейти (ТЗ: «всплывающие окна … не предусматриваются»). События `MarkerClickEvent` в окне 4.2 **не настраиваются**.

## 3. Программа ST

### 3.1. Нужна ли программа
ТЗ прил. 2 для ПБЭ № 4 требует два окна и не требует программной обработки. Однако:
* параметр `СостояниеN` должен **вычисляться** по приоритету (авария > нет связи > работа > стоп) — это «преобразование значений» из ТЗ п. 1.4;
* параметры группы `КолРаботают`, `КолАварий`, `ДиагНетСвязи`, `ЕстьАвария` — агрегаты по пяти установкам.

Поэтому программа **присутствует, но минимальна**: она только преобразует и агрегирует, ничего не записывает в оборудование. Это не противоречит требованию «только мониторинг»: направления записи в оборудование нет.

```st
   Только мониторинг. Команды в оборудование НЕ формируются.
   Аварии приходят отдельными BOOL - разбор битовых масок не выполняется
   (ТЗ, п. 3; ТЗ, приложение 1, часть 2, ПБЭ № 4).
   ============================================================================ *)

VAR
    i : INT;
END_VAR

(* ---- Состояние установки 1 (В1.1) ---- *)
(* Приоритет: авария > нет связи > работа > стоп.
   Значения: 0 - Стоп, 1 - Работа, 2 - Предупреждение, 3 - Авария, 4 - Нет связи *)
IF АвАвария1.Value THEN
    Состояние1.Value := 3;
ELSIF ДиагНетСвязи1.Value THEN
    Состояние1.Value := 4;
ELSIF Работа1.Value THEN
    Состояние1.Value := 1;

    Состояние1.Value := 0;

ELSIF Состояние1.Value = 2 THEN
    Состояние1Текст.Value := 'Предупреждение';
ELSIF Состояние1.Value = 3 THEN
    Состояние1Текст.Value := 'Авария';
ELSE
    Состояние1Текст.Value := 'Нет данных';
END_IF;

    Заслонка3Текст.Value := 'Закрыта';
ELSE
    Заслонка3Текст.Value := 'Нет данных';
END_IF;

IF NOT НастрЕстьЗаслонка4.Value THEN
    Заслонка4Текст.Value := 'Нет данных';
ELSIF ЗаслонкаОткрыта4.Value THEN
    Заслонка4Текст.Value := 'Открыта';
ELSIF ЗаслонкаЗакрыта4.Value THEN
    Заслонка4Текст.Value := 'Закрыта';
ELSE
    Заслонка4Текст.Value := 'Нет данных';
END_IF;

IF NOT НастрЕстьЗаслонка5.Value THEN
    Заслонка5Текст.Value := 'Нет данных';
ELSIF ЗаслонкаОткрыта5.Value THEN
    Заслонка5Текст.Value := 'Открыта';
ELSIF ЗаслонкаЗакрыта5.Value THEN
    Заслонка5Текст.Value := 'Закрыта';
ELSE
    Заслонка5Текст.Value := 'Нет данных';
END_IF;

(* ---- Агрегаты группы ---- *)
(* Считаем по вычисленным признакам, чтобы агрегат не зависел от порядка
   выполнения отдельных присваиваний выше *)
КолРаботают.Value := 0;
КолАварий.Value   := 0;

FOR i := 1 TO 5 DO
    IF i = 1 THEN
        IF Состояние1.Value = 1 THEN КолРаботают.Value := КолРаботают.Value + 1; END_IF;
        IF ЕстьАвария1.Value THEN КолАварий.Value := КолАварий.Value + 1; END_IF;
    ELSIF i = 2 THEN
        IF Состояние2.Value = 1 THEN КолРаботают.Value := КолРаботают.Value + 1; END_IF;
        IF ЕстьАвария2.Value THEN КолАварий.Value := КолАварий.Value + 1; END_IF;
    ELSIF i = 3 THEN
        IF Состояние3.Value = 1 THEN КолРаботают.Value := КолРаботают.Value + 1; END_IF;
        IF ЕстьАвария3.Value THEN КолАварий.Value := КолАварий.Value + 1; END_IF;
    ELSIF i = 4 THEN
        IF Состояние4.Value = 1 THEN КолРаботают.Value := КолРаботают.Value + 1; END_IF;
        IF ЕстьАвария4.Value THEN КолАварий.Value := КолАварий.Value + 1; END_IF;
    ELSIF i = 5 THEN
        IF Состояние5.Value = 1 THEN КолРаботают.Value := КолРаботают.Value + 1; END_IF;
        IF ЕстьАвария5.Value THEN КолАварий.Value := КолАварий.Value + 1; END_IF;
    END_IF;
END_FOR;

ЕстьАвария.Value := КолАварий.Value > 0;

ДиагНетСвязи.Value := ДиагНетСвязи1.Value
                  OR ДиагНетСвязи2.Value
                  OR ДиагНетСвязи3.Value
                  OR ДиагНетСвязи4.Value
                  OR ДиагНетСвязи5.Value;

(* Конец программы ПБЭ № 4 *)
```

### 3.3. Пояснения к программе

| Что | Пояснение |
|---|---|
| Отдельные BOOL вместо маски | `АвАвария1…5` — BOOL. Разбор битовых масок **не выполняется**, т. к. ТЗ п. 3 прямо запрещает его в этом случае |
| `GetBit` не используется | Маски DINT в ПБЭ № 4 отсутствуют, следовательно применять `GetBit` не к чему |
| Приоритет состояния | Авария (3) → Нет связи (4) → Работа (1) → Стоп (0). Порядок `IF/ELSIF` задаёт приоритет |
| `ЕстьАварияN` | Авария считается действительной только при наличии связи: `АвАварияN AND NOT ДиагНетСвязиN`. Иначе потеря связи маскировалась бы под аварию |
| Заслонка при `Настр… = FALSE` | Текст принудительно «Нет данных»; графика скрыта связью на «Видимость» (см. §1.4, строка 7). **Команды по отключённой функции не формируются** — их в ПБЭ № 4 нет вообще |
| `КолУстановок` | Параметр-настройка присутствует, но цикл агрегации написан явно по пяти установкам: это надёжнее и не зависит от поддержки массивов параметров в версии 1.3.10 |
| Запись в оборудование | Отсутствует. Ни одного присваивания параметру направления «Вх» |

### 3.4. Проверка синтаксиса, выполненная при разработке
* Все используемые конструкции — `IF/ELSIF/ELSE/END_IF`, `FOR/END_FOR`, присваивание `:=`, комментарии `(* *)`, логические `AND`/`OR`/`NOT`, сравнения `=`/`>`. Функции из библиотеки не вызываются вовсе — значит, риск несуществующего API равен нулю.
* Имена параметров соответствуют таблице `параметры.md`.
* В `VAR` объявлена одна переменная `i : INT` — по образцу рис. А.2 (там `VAR` содержит локальные `i, n, k, s, v`).

## 4. Видимость обозначений при потере связи

**Требование ТЗ п. 3:** «Обозначение установки и обслуживаемые помещения задаются параметрами в проекте и остаются видны при потере связи с оборудованием».

**Как выполнено:**
| Объект | Параметр | Связь с `ДиагНетСвязиN` |
|---|---|---|
| `Текст_ОбозначениеN` | `ОбозначениеN` (настройка, STRING) | **Нет связи** — значение из проекта |
| `МеткаN_Обозначение` | `ОбозначениеN` | **Нет связи** — значение из проекта |
| `Текст_ПомещениеK` | `ПомещениеK` | **Нет связи** |
| `Текст_ПомещениеKНазначение` | `ПомещениеKНазначение` | **Нет связи** |
| `Текст_НазваниеГруппы` | `Название` | **Нет связи** |

Обозначения и помещения берутся из параметров-**настроек**, которые не зависят от канала. Поэтому при обрыве связи они остаются на экране, а меняются только индикаторы состояния. Это проверяется тестом **T-14**.

## 5. Обоснование отсутствия программы разбора аварий

ТЗ п. 3: «Если контроллер передаёт аварии отдельными логическими признаками (без масок), программа разбора не разрабатывается, а текст аварии формируется по признаку».

ПБЭ № 4 работает с вытяжными установками без ПЛК: сигналы приходят дискретными признаками (`РаботаN`, `АвАварияN`). Следовательно:
* параметров-масок типа `АварияКрит1 : DINT` в ПБЭ № 4 **нет**;
* вызовов `GetBit` в программе **нет**;
* текст аварии формируется по признаку — параметр `СостояниеNТекст` принимает значение «Авария» напрямую.

Это соответствует **требованию** ТЗ, а не является упрощением.

## 6. Сообщения, тренды, архивирование

| Средство | Статус | Основание |
|---|---|---|
| Сообщения | **Не предусмотрены** | ТЗ прил. 1 ч. 2 (ПБЭ № 4): перечень запрещённого не включает сообщения прямо, но ПБЭ «предназначен только для мониторинга», а окна «Строка аварий» у № 4 нет — журнал аварий ведётся на уровне раздела (шапка/строка аварий других ПБЭ). Во избежание двойного журналирования сообщения в ПБЭ № 4 **не создаются** |
| Тренды | **Не предусмотрены** | ТЗ прил. 1 ч. 2: «тренды … не предусматриваются» |
| Архивирование | **Не предусмотрено** | ТЗ прил. 1 ч. 2: «архивирование не предусматривается» |

**Проверка при сборке:** ни один параметр ПБЭ № 4 не должен иметь включённого признака `Архивировать`. Это тест **T-16**.

> **Внимание.** Если ДИГАМ потребует журналировать аварии группы, это делается **не** в ПБЭ № 4, а через окна «Строка аварий» соответствующего раздела; тогда решение оформляется отдельным изменением и согласуется, поскольку прямо затрагивает запрет ТЗ.
