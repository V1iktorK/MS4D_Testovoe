## 1. Цель этапа 1

Создать **фундамент**, на котором все 8 ПБЭ делаются единообразно, и довести до состояния «можно вбивать в среду» **первый ПБЭ**.

Почему так: 8 ПБЭ — это ~87 окон, из которых 5 окон-шаблонов повторяются во всех восьми (Мнемосхема, Строка, Строка состояния, Строка аварий, Точки на плане), а 4 окна — у всех, кроме № 4 (Настройки, 3 тренда). Если соглашения по именам, типам и конвертерам не зафиксировать **до** первой графики, переделывать придётся всё.

**Порядок ПБЭ:** № 4 → № 3 → № 2 → № 1 → № 6 → № 7 → № 8 → № 5 (приоритет из [S6]).
* № 4 — самый простой (2 окна, только мониторинг) → на нём обкатываются конвенции;
* № 3 — заготовка, обкатывается каркас вытяжной мнемосхемы;
* № 2 — обкатываются моточасы и ротация;
* № 1 — **эталонный ПБЭ**, самый полный (маски DINT + BOOL, планировщик, влажность, ККБ);
* № 6, 7, 8 — вариации № 1 (вытяжка µAria, приток µAria, Zentec);
* № 5 — особая конструкция (групповой экземпляр, блочные строки/метки).

## 2. Состав работ этапа 1

### 2.1. Общие соглашения (документ `10_Общие_соглашения.md`)
1. **Каркас ПБЭ** — имена групп: `Ресурсы → Программы`, `Ресурсы → Сообщения`, `Ресурсы → Окна` (по рис. А.1).
2. **Соглашение об именах параметров** — префиксы по назначению: `Название`, `Обозначение`, `Вкл…`/команды, `Ав…`/аварии, `Т…`/температуры, `Уст…`/уставки, `Зад…`/задания, `Настр…`/настройки экземпляра, `План…`/планировщик, `Вр…`/времена и задержки, `Мч…`/моточасы, `Выб…`/выборы.
3. **Соглашение об именах графических объектов** — по образцу рис. А.5: `<№> <День недели> <№ интервала> <Что>`, например `3 Пятница 2 Начало час`. Для остальных окон: `<Окно>_<Поле>`.
4. **Типы параметров** — таблица «что каким типом» (§2.2 ниже).
5. **Конвертеры** — цвета только `rgb(...)`; строка `False` в булевом конвертере идёт **первой**; цвет текста `#RRGGBB`.
6. **Связь** — правило «пишет ⇒ читает»: у любого элемента, записывающего значение, заполнены и «Входящие связи», и «Исходящие связи».
7. **Кнопки** — только `Action.SetParameter` / `Action.OpenDialog` по событию. Никаких прямых записей в тег.
8. **Видимость** — входящая связь на свойство «Видимость» группы (по рис. А.3) + флажок «Скрывать при отсутствии…».
9. **Изоляция варианта** — переключаемые функции гасятся настройкой экземпляра: невидимая графика + параметр-признак, по которому ST **не формирует** команду (ТЗ п. 1.3, 3.2).

### 2.2. Таблица типов параметров (`11_Типы_параметров.md`)
Разово фиксируется: BOOL — команды, признаки, аварии-признаки; REAL — температуры, влажность, проценты, уставки аналоговые; INT — часы/минуты расписания, номера, моточасы в часах; DINT — **маски аварий** (ТЗ п. 3) и счётчики; TIME — задержки, времена хода заслонок; STRING — обозначения, тексты аварий, назначения помещений; перечисления — режимы, сезон, выбор вентилятора.

### 2.3. Каркас пяти общих окон (`12_Каркас_общих_окон.md`)
По Приложению 2 ТЗ: «Шапка состояния» + «Строка состояния» (пара `Journal.Header`/`Journal.Row`), «Шапка аварий» + «Строка аварий» (вторая пара), «Строка» (сводная), «Точки установок на плане» (метка). С обязательной проверкой: **число полей в шапке = числу полей в строке**.

### 2.4. ПБЭ № 4 — полный комплект (первый готовый ПБЭ)
* паспорт; таблица параметров (5 установок × независимая индикация); эскиз окна 4.1 и 4.2; карта связей; ST не требуется (по ТЗ — только мониторинг, органы управления/уставки/расписание/тренды/архивирование не предусмотрены) → вместо ST фиксируется **явное обоснование отсутствия программы**;
* тестовые сценарии; пошаговая инструкция сборки.

### 2.5. Шаблоны документов для остальных ПБЭ
`90_Шаблоны.md` (раздел «Шаблон паспорта ПБЭ») — чтобы ПБЭ № 3…8 и № 5 описывались одинаково и ДИГАМ мог их сравнивать.

## 4. Тестовые сценарии приёмки этапа 1 (прогоняет пользователь)

Полные сценарии — в `13_Тесты_этапа_1.md`. Кратко, что должно подтвердиться:

**T1. Структура пустого ПБЭ.** Создан элемент с тремя группами ресурсов и параметрами. Ожидание: дерево совпадает с `00_…` §3 рис. А.1.

**T2. Конвенции имён.** Выборка 10 случайных параметров. Ожидание: каждый попадает в префиксную схему, ни одного «Параметр1».

**T3. Конвертер цвета.** Булев параметр «ЕстьАвария» → конвертер. Ожидание: цвета заданы как `rgb(...)`; в булевом конвертере значение `False` стоит **первой** строкой.

**T4. Связь «пишет ⇒ читает».** Поле ввода уставки. Ожидание: заполнены обе секции связей.

**T5. Кнопка через действие по событию.** Кнопка «СБРОС». Ожидание: в событиях — `Задать параметр` (`Action.SetParameter`), не прямая запись.

**T6. Скрытие варианта.** Группа графики с входящей связью на «Видимость». Ожидание: при `FALSE` группа исчезает, при `TRUE` появляется; «Скрывать при отсутствии…» работает.

**T7. ПБЭ № 4, окно 4.1.** Пять установок, у каждой своя индикация. Ожидание: изменение сигнала одной установки **не влияет** на остальные четыре.

**T8. ПБЭ № 4, окно 4.2.** Пять точек на плане. Ожидание: пять отдельных меток, у каждой имя, состояние и температура.

**T9. ПБЭ № 4 — отсутствие запрещённого.** Ожидание: нет ни одной кнопки, ни одного поля уставки, ни тренда, ни архивной настройки.

**T10. Число окон.** Ожидание: у ПБЭ № 4 ровно 2 окна, номера 4.1 и 4.2, наименования — дословно по Перечню.
