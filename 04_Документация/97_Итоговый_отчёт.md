### 2.2. Что дал Пример ПБЭ

**Рисунок А.2** содержит **дословный ST-код** разбора аварий — он стал основой для ПБЭ № 1:

```st
v := ВариантАварий.Value;
IF v = 0 THEN v := 1; END_IF;
IF v = 4 THEN
    Пожар.Value := GetBit(IN := АварияКрит1.Value, N := 0);
    ...
    n := 0;  k := -1;
    FOR i := 0 TO 8 DO
        IF GetBit(IN := АварияКрит1.Value, N := i) THEN
            n := n + 1;
            IF k < 0 THEN k := i; END_IF;
        END_IF;
    END_FOR;
    ЕстьАвария.Value := n > 0;
```

Из этого кода извлечено **семь принципиальных фактов**, определивших всю разработку:
1. `GetBit(IN := …, N := …)` — **именованные аргументы**;
2. маска хранится в **DINT**;
3. вариантов разбора несколько, переключаются параметром `ВариантАварий`;
4. биты 5 и 6 (вентиляторы) **учитываются в подсчёте, но не разбираются** — «приходят отдельными точками»;
5. `КодАварии` = младший бит, `-1` при отсутствии;
6. локальные переменные объявляются в `VAR … END_VAR` внутри программы;
7. комментарии — в форме `(* … *)`.

**Рисунки А.3–А.6** дали свойства связей: `rgb(240,240,240)` для цвета тени, `#202020` для текста, `Приток~Помещение` для списка, `Минимум 0 / Максимум 100 / Текущее значение 50` для поля ввода, структуру сообщения из 9 элементов с типом `BOOL`.

**Рисунки 1.1–1.8** — образцы окон, причём для ПБЭ № 1 они соответствуют позициям 1.1–1.8 Перечня **дословно**.

## 3. Результат по каждому ПБЭ

### ПБЭ № 1 — Carel pCO XS / c.pCO / µAria (**эталон**)

| Показатель | Значение |
|---|---|
| Окон / экземпляров | 13 / **18** (8 + 1 + 9) |
| Параметров | ~306, включая **121 параметр планировщика** |
| ST-код | **803 строки, 9 разделов** |
| Тестов | 75 (30 критичных), прогон **× 3 варианта** |

**Ключевые решения:**
* **Три варианта оборудования в одном типе.** Различие — настройками экземпляра, не отдельными типами (ТЗ п. 1.1).
* **Два независимых пути аварий.** Разбор масок DINT для pCO XS/c.pCO; для µAria разбор **отключён** (`НастрРазборМаски := FALSE`). ТЗ требует и то, и другое.
* **Биты 5 и 6 учитываются в подсчёте `n`, но отдельных параметров не создают** — дословно по рис. А.2.
* **Влажность для µAria не выводится** — принудительно гасится настройкой.
* **Планировщик**: 7 дней × 2 интервала, полуинтервал `[Начало, Конец)`, ночные интервалы, приоритет интервала 2. Команды формируются **только через параметры ПБЭ**.

### ПБЭ № 2 — Schneider M172

| Показатель | Значение |
|---|---|
| Окон / экземпляров | 12 / 6 |
| Параметров | ~147 |
| ST-код | **394 строки, 9 разделов** |
| Тестов | 64 (23 критичных) |

**Ключевые решения:**
* **Снимки обратной связи в начале программы** — роли вентиляторов меняются в середине, без снимков наработка начислялась бы не тому вентилятору.

* **Ротация по наработке** — требование ТЗ именно для № 2.
* **Особая нумерация окон:** мнемосхема = **2.12**, таблицы 2.1–2.4 первыми. Зафиксировано как предупреждение — «причесать» нумерацию значит нарушить Перечень.

### ПБЭ № 5 — VRF LG / Electrolux / MDV

| Показатель | Значение |
|---|---|
| Окон / экземпляров | 9 / **3** |
| Параметров | **≈ 903** (MDV: 66 блоков × 12 + 7 × 10 + 42) |
| ST-код | **2018 строк, 7 разделов** (разделы 4, 5, 6 — по 66 индексов) |
| Тестов | 51 (24 критичных) |

**Ключевое:** конструкция принципиально отличается от всех остальных — **один экземпляр = вся система корпуса** с десятками блоков.

**Найденная проблема и её решение.** Прямой расчёт: LG ≈ 481, Electrolux ≈ 514, **MDV ≈ 558** параметров. После сокращений (тексты → в конвертеры, назначения помещений → в справочник) ≈ **903** — втрое больше любого другого ПБЭ. **Предел числа параметров типа не задокументирован** ни в переданных материалах, ни в реестрах проверенной сборки 1.3.10.37086. Поэтому в инструкции по сборке это **шаг 0** — до основной работы, с тремя сценариями. Вариант «вынести блоки наружу» **противоречит ТЗ** и не применяется.

**Механизм «выбранного блока»** (требование «команды относятся к выбранному блоку»): строки таблиц пишут прямо в свой индекс; для плана и трендов программа копирует параметры блока с индексом `ВыбранныйБлок` в служебные `ВыбранныйБлок…`; клик по метке устанавливает выбор.

**Охват индексов — полный:** программа реализует копирование выбранного блока, обратную запись команд и сводную агрегацию для **всех 66 индексов** (разделы 4, 5 и 6 — по 66 ветвей). Параметр `СтраницаБлоков` влияет **только на отображение** (окна 5.4 и 5.7 показывают страницу из 10 строк вместо 66) и на логику не влияет.

### ПБЭ № 6 — Carel µAria, вытяжка, корпус 8

| Показатель | Значение |
|---|---|
| Окон / экземпляров | 13 / **13** (ШУВ1 = 3, ШУВ2 = 10) |
| Параметров | ~304 |
| ST-код | **1031 строка, 11 разделов** |
| Тестов | 80 (32 критичных) |

**Три новых механизма по ТЗ:**
* **Групповые параметры общего шкафа** (18 шт.) — «индивидуальные сигналы установок и общие команды группы обозначаются отдельно». Ключевое: **групповая команда дополняет индивидуальную, а не подменяет её** — иначе оператор потерял бы управление своей установкой.
* **Задержки тревог** (3 параметра) — кратковременный сигнал не должен давать ложную тревогу. Тест T6-27: подать признак на 5 с при задержке 30 с — тревоги быть не должно.
* **Индикация основной/резервной работы** — четыре состояния.

**Защита от ошибочного переноса:** ТЗ для № 6 требует **индикации**, а ротация — требование **только** № 2. Если перенести ротацию из № 2, получится функция, которой ТЗ не требует, и вентиляторы начнут самовольно переключаться. В программе ротации нет, есть **негативный тест T6-41**.

### ПБЭ № 7 — Carel µAria, приток, корпус 22

| Показатель | Значение |
|---|---|
| Окон / экземпляров | 13 / 3 |
| Параметров | ~275 |
| ST-код | **686 строк, 8 разделов** |
| Тестов | 64 (24 критичных) |

**Ключевое:** ТЗ прямо задаёт состав «как у варианта µAria ПБЭ № 1». Работа свелась к аккуратному вычитанию.

**Главная находка: семь аварийных признаков меняют направление с «Выч» на «Вх».** В ПБЭ № 1 параметры `Пожар`, `АвЗаслВыт`, `АвЗаслПрит`, `АвПолохЗаслРецВыт`, `АвПолохЗаслРецПрит`, `НизкаяТПомещения`, `ОбрывТПомещения` были **вычисляемыми** (`GetBit`). Здесь маски нет, поэтому они принимаются **от канала**. Если при копировании забыть — параметры останутся вычисляемыми, вычислять их будет нечем, и **все семь аварий навсегда FALSE**. Добавлен отдельный тест T7-18 на направление.

### ПБЭ № 8 — Zentec M245

| Показатель | Значение |
|---|---|
| Окон / экземпляров | 13 / **8** (В7 и В8 — отдельные при общем ШВ7.8) |
| Параметров | ~330 |
| ST-код | **1086 строк, 11 разделов** |
| Тестов | 80 (36 критичных) |

**Ключевые решения:**
* **Имена параметров = коды производителя:** `АвA001`…`АвA007`. ДИГАМ подключает теги Zentec **без переименования**.
* **Сброс зуммера отделён от сброса аварий — и найдена тихая ошибка.** Если признак `ЗуммерОтключенОператором` **не сбрасывать** при снятии всех аварий, то после **первого** нажатия зуммер молчал бы **всегда**: авария пришла, а оператор не узнал. Исправлено, есть тест **T8-28** именно на это.
* **Признак «в промежуточном положении»** — для клапана вентиляции застревание между положениями самостоятельная неисправность. Отнесено к **предупреждениям**, не к авариям.
* **Общий шкаф не объединяет В7 и В8** — ТЗ прямо оговаривает, что это отдельные экземпляры.

### 7.2. Переработка планировщика (следствие ответа № 3)

Функции получения текущего времени в среде **нет**. Это ломало планировщик ПБЭ № 1, 6, 7, 8 — он вычислял день недели и часы из строки даты, полученной несуществующей функцией.

**Решение.** День недели и время суток теперь **принимаются входными параметрами**:

| Параметр | Тип | Направление | Значения |
|---|---|---|---|
| `СистемаДеньНеделиТекст` | STRING | **Вх** | `Пн` … `Вс` |
| `СистемаЧас` | INT | **Вх** | 0…23 |
| `СистемаМин` | INT | **Вх** | 0…59 |

**Это соответствует ТЗ п. 3:** «Элемент работает со своими параметрами, без подключения к конкретному контроллеру. Например, графика показывает параметр элемента «Температура»; к тегу нужной установки его подключает ДИГАМ». Тот же принцип применён ко времени: **к системному тегу времени эти три параметра подключает ДИГАМ**.

**Что изменено:**

| Было | Стало |
|---|---|
| `GET_LOCAL_TIME` → `DT_TO_STRING` → `MID` → день/час/минута | три входных параметра + ограничение значений |
| 13 вызовов функций в ПБЭ № 1, 6, 7, 8 | 0 вызовов |
| 4 вызова `GET_LOCAL_TIME` в ПБЭ № 2 (метка времени переключения) | удалены; параметр `ВрПоследнегоПереключения` сделан **входным**; логика ротации и АВР от него **не зависит** |
| Зависимость от формата строки даты | зависимость снята |

**Проверено:** в коде всех 8 программ — `GET_LOCAL_TIME` = 0, `DT_TO_STRING` = 0, `STRING_TO_INT` = 0, одинарных кавычек = 0.

**Доработано:** ПБЭ № 5 — охват **всех 66 индексов** (разделы 4, 5, 6 переписаны, файл 2018 строк); ПБЭ № 6 — добавлена **логика сезона** (раздел 11); ПБЭ № 1 — `ПланАктивныхИнтервалов` теперь вычисляется. Подробности — §7.6.
