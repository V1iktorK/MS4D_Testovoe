# 010. Реестр фактов установленной сборки MasterSCADA 4D 1.3.10.37086

**Назначение.** Зафиксировать, что именно проверено в фактически установленной сборке, каким методом и какие утверждения комплекта этим подтверждены или исправлены. Документ дополняет `02_API_MasterSCADA_проверенный.md` (там — свод правил API) и является источником для `100_Пошаговая_инструкция.md`.

**Дата проверки:** по состоянию установки, версия ниже.
**Кто проверял:** разработчик комплекта — сверка выполнена разбором XML-реестров установки (`Types\**\*.xml`, `Properties\**\*.xml`) и словаря справки.

## 5. Что подтвердить не удалось (и почему)

| Что | Почему | Как поступить |
|---|---|---|
| Пункт меню создания **библиотечного элемента** | в реестрах типов такого узла нет; словарь справки содержит «Создание библиотеки» и «Создание компонента» | В инструкции оставлена пометка `(?)`: смысл однозначен («добавить элемент в раздел Библиотеки»); уточнить по факту меню |
| Команда **экспорта библиотеки** в `.mslb` | ни в реестрах, ни в справке подписи нет; готовой библиотеки в поставке нет | Оставлена пометка `(?)` и порядок действий по смыслу; уточнить по факту меню |
| Прямой SQL-доступ к базам `DEFAULT.FDB` / `MasterSCADA.Library.HMI.fdb` / `Examples.fdb` | базы принадлежат учётной записи поставщика; подключение от текущего пользователя отклоняется с «no permission for read/select access to TABLE TYPES». Учётные данные владельца в комплект не входят | Реестр типов взят из **XML-реестров** установки (`Types\**\*.xml`) — это тот же перечень, из которого среда строит таблицу `TYPES` проекта. Итог: 1 529 имён против 818 в прежней сборке |
| Число графических объектов в окнах | определяется составом окна конкретного ПБЭ (ТЗ: не критерий приёмки) | Не проверяется |

> Метод нельзя подменять догадками: если понадобится чтение именно `.fdb`, нужен либо экспорт проекта средствами среды (это делает пользователь), либо учётные данные владельца базы.

### 5.1. Что делать с SQL — коротко

| Ситуация | Действие |
|---|---|
| Нужен **список типов, функций, подписей** (то, что нужно сейчас) | SQL **не нужен** — всё берётся из XML-реестров установки. Выполнено |
| Нужна **схема Базы проекта** (строки, свойства окон, конвертеры конкретного ПБЭ) | Читать **свой** проект: создать проект из шаблона средствами среды (это делает пользователь) — база будет принадлежать вашей учётной записи, ограничений нет |
| Нужна база из поставки (`DEFAULT.FDB`, `MasterSCADA.Library.HMI.fdb`, `Examples.fdb`) | Запросить у поставщика (ДИГАМ/MPSSoft) учётные данные владельца либо экспорт проекта. Иначе чтение блокируется правами — обход не применяем |
| Прислали `.fdb` | Читать на копии файла клиентом Firebird 2.5 из поставки (`fbembed.dll`); встроенный сервер даёт монопольный доступ |

**Правило:** SQL к базам поставки без прав владельца не «взламываем» — берём эквивалентный текстовый источник (XML-реестры) или просим экспорт.

## 7. Как повторить проверку вручную

1. Открыть `bin\MasterPLC\Config\Types\` установленной сборки и собрать перечень имён типов и подписей `DisplayName` (62 файла реестра).
2. Сверить с перечнем, который используют документы комплекта и ST-программы: 4 функции ST (`CONCAT`, `GetBit`, `LIMIT`, `TIME_TO_INT`) — присутствуют, исчезнувших типов нет, добавилось 84 новых.
3. Сверить подписи пунктов меню и свойств с `100_Пошаговая_инструкция.md`: расхождения перечислены в §6.
